# YFFM1 V3.3：战术执行与反馈

完成日期：2026-11-13。新比赛默认 `3.3.0` / `v3.3-tactical-execution.1` / `match-engine-v3.3`。项目版本仍为 0.3.0。修改及构建在本地完成，未推送或部署。

升级前备份：`outputs/backups/engine-before-v33-20261113-105310/`。

## 玩家可用内容

在“阵容战术 → 球队战术原则”中，为默认、领先、落后三套预案分别配置：

| 模块 | 新设置 | 实际作用与限制 |
| --- | --- | --- |
| 出球与接应 | 左/中/右侧优先；后腰接应或中锋支点；受压保持、转移或直接出球 | 只提高可行路线和可达接应点的优先级；弱侧转移要求跨侧且压力更低，额外消耗处理时间；直接出球牺牲连接质量 |
| 压迫与针对性防守 | 对方回传、边线接球、进入本方半场；上抢/封线分工；限制组织者、中锋或边路 | 按当前球区、上一实际动作和对手当前职责分配附近防守人；上抢与保护分工，移动受速度和距离约束，参与者额外消耗体力 |
| 定位球战术 | 近点、远点、短角球；均衡、保护或增加抢点 | 抢点、二点和留守使用不同人员；18 秒组织，短角球传接和二点争夺另计时间；失去球权后保留实际位置进入转换 |
| 条件预案与轮换 | 比分预案最早启用时间；体力/黄牌轮换；开始时间与体力阈值 | 比分与时间同时满足才切换；预案切换间隔至少 2 个足球分钟；主动轮换至少间隔 5 分钟，使用合适替补，体力条件要求替补高 5 点以上 |

条件轮换、伤退换人和门将红牌应急共用每队最多 5 人的限制；换下球员不能再次上场。主动轮换默认关闭。时间条件仅限制领先/落后预案，默认预案不受其限制。设置在行动链边界检查，比赛开始后使用锁定的预案；未新增手动实时指令接口。

“常规判断 / 自由接应 / 均衡落点”等默认值保持原有策略路径。角球两项均默认时沿用旧角球；任意球和点球仍使用原有规则。快捷预设目前提供原原则与 V3.2 建议，不覆盖用户已配置的 V3.3 项目。

保存、撤销、方案切换、导出导入和完整镜像上传沿用同一字段校验。非法枚举值拒绝保存，不能部分写入。

## 界面与反馈

- 队长、风格、领先/落后比分节点、导入导出和镜像上传常驻顶部，不再折叠。
- 删除各选择项下方的常驻说明，必要解释放入控件悬停提示。
- 电脑端右侧面板按窗口剩余高度限制，展开内容在面板内滚动；战术板完整显示。侧栏不再使用战术页专用缩小规则，与联赛总览保持一致。
- AI 对战、玩家镜像仍是常驻入口；批量/服务器模拟入口继续隐藏。
- 直播增加实际压迫、重点盯防和出球处理记录，附行动人员、球区与结果；普通战术动作最多每 8 条链展示一次，不挤占重点事件置顶。
- 终场直播和历史战报增加“战术执行复盘”：触发压迫、随后夺回、参与人秒、盯防、指定出球、备用路线、角球射门/二点、条件轮换及球权丢失较多区域。

这些是过程统计，同一动作可以计入多个战术。记录先后关系，不代表某次失误或进球由某条指令单独造成。雷达仍是静态阵容投影，不能直接表达所有比赛中的条件指令效果。

## 64 场过程检查

固定同能力 4-3-3、晴天、标准裁判，每个场景 4 个种子、双方换边，共 64 场。原始数据：`outputs/v33-calibration/`。

| 场景（每项 8 场） | 观察结果 |
| --- | --- |
| V3.2 与 V3.3 全默认 | 两组平均总进球均 4.00、总射门 38.50、链数 269.625；这组样本的主要结果一致 |
| 边线压迫 | 690 次触发，随后夺回 269 次；5130 参与人秒，承担额外负荷 |
| 回传封线 + 限制组织者 | 重点盯防 2346 次；回传触发仅 1 次，说明该条件受对手实际动作频率限制 |
| 左侧优先 + 后腰接应 | 指定出球 1206 次，完成 808 次 |
| 近点 + 增加抢点 | 套路角球 99 次，形成射门 49 次，二点夺回 23 次 |
| 远点 + 留守保护 | 套路角球 106 次，形成射门 52 次，二点夺回 21 次 |
| 短角球 + 均衡 | 套路角球 106 次，形成射门 38 次，二点夺回 13 次 |

它们是探索性过程检查，不是不同套路的因果胜率比较。样本中的队伍、阵型和能力范围有限，尚未完成完整战术交互矩阵或证明 V3.3 比 V3.0 全局比分波动更低。需要继续监测角球频率、压迫效果、能力差及不同阵型的交互。新版仍是区域式轻量模型，不是完整物理比赛模拟。

## 本机体验

```powershell
cd D:\YFFM1
npm run build
npm start
```

停止旧服务后启动，刷新浏览器。在“阵容战术”修改新模块，等待“已实时保存”，刷新确认保留，再开一场 AI 对战。终场直播下方可查看战术执行复盘。配置接口 `/api/versus/config` 应显示 `engineVersion: "3.3.0"`；已开赛的旧比赛继续沿用旧版本。

```powershell
npm run test:engine:v33
npm run diagnose:engine:v33
npm run calibrate:engine:v33 -- --quick
```

诊断输出 `outputs/v33-diagnostic/report.json`，`exactResume` 应为 `true`。这些脚本使用合成球队/临时数据，不访问实际联赛资产。

## 相比 V3.0 的进步

| 方面 | V3.0 | V3.3（含 V3.1、V3.2） | 玩家得到什么 |
| --- | --- | --- | --- |
| 比赛时间 | 常规比赛固定 180 条链 | 每次行动消耗足球时间，球权、持球者、球区与实际位置持续保存 | 快处理、耐心组织、拖延和转换真正改变剩余机会 |
| 行动选择 | 主要按阶段及候选权重选路线/人员 | 比较少量可行行动，只让价值相近的候选保留变化 | 指定出球、受压转移和接应配置更直接影响行为 |
| 防守操作 | 防守方向、宽度、区块及强度 | 增加触发式上抢/封线、保护分工、重点盯防、短时反抢/回撤与留守 | 能配置何时投入、投入谁、如何保护，并承担相应位置与体力代价 |
| 定位球 | 主要由主罚人、能力及既有流程决定 | 明确近点/远点/短角球、抢点/二点/留守分工 | 多了可选择的配合过程与人员投入取舍 |
| 预案与换人 | 主要由比分触发预案，伤退/门将应急 | 增加时间门槛、切换冷却、体力/黄牌条件轮换 | 可以预先安排比赛不同阶段的应对 |
| 随机性与恢复 | 已有分组抽样，但旧检查点未完整保存普通随机源 | 分领域随机流、完整状态保存、配置锁定和精确续跑 | 重启或分批计算不应意外重抽未来比赛；不等于比赛结果完全确定或全局波动已进一步下降 |
| 比分影响 | 还有通用领先/落后阶段与质量修正 | 移除这些通用直接概率补偿，主要通过所配预案改变行为 | 比分后的打法变化更容易对应玩家配置 |
| 反馈 | 事件、赛果、统计与空间评估为主 | 增加实际行动反馈、概率诊断、战术执行与代价复盘 | 能区分没有触发、已经执行和执行后丢球，而不只根据输赢猜效果 |

核心提升是战术从“参数倾向”扩展为带时间、空间和人员约束的行为规则，并且能保存、复现和检查执行过程。仍需更大规模真实阵容样本验证平衡；目前不能承诺某个随机性下降百分比。
