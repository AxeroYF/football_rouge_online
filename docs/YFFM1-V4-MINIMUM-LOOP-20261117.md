# V4 最小闭环：空间、任务、解释与小圆点

日期：2026-11-17。版本：`4.0.0-prototype.1`。

本文保留第一阶段记录。当前已升级至 prototype.2，协同、转换、接球失误、扑救脱手和二点争夺见 [第二阶段说明](YFFM1-V4-COORDINATION-20261117.md)。

独立原型已实现。正式联赛仍使用现有引擎，预测仍为V1/24样本；未接入资产结算、真实存档或正式服务器入口。

## 使用

在 `D:\YFFM1` 运行：

```powershell
npm run dev:v4
```

打开 http://127.0.0.1:4314 。更换端口：`node scripts/serve-v4-lab.mjs --port=4315`。

该静态服务只绑定本机回环地址，只提供 `versus/v4` 内的HTML/CSS/JS，不加载 `.env`、联赛服务或账号数据。浏览器Worker运行合成阵容模拟。

操作：选择双方战术和重复编号，生成3/5/10分钟片段；播放/暂停、0.5–16倍速、射门阶段自动慢放、拖动时间线、点击事件回看；点击球员或通过选择器观察任务与目标。

本阶段是离线生成后的本地回放，不是正式比赛的服务器实时流。它先打通相同状态驱动判定、解释和画面；多人发布进度和网络增量订阅尚未实现。

## 已实现

- 105×68米世界坐标、双方独立球员实例（即使球员ID相同）、位置、速度、朝向、体能和任务状态。
- 固定0.2足球秒推进；双方基于同一位置快照规划，再统一移动；加速与速度限制、局部分离。
- 球的持有、飞行、自由和死球状态。当前球路为地面直线，`z`保留为0；未实现高球和弧线。
- 战术预设：均衡接应、左侧套上、高位压迫、低位反击。包含回接、拉开、前插、套上、留守、上抢、封线、跟防、回撤、接球与自由球争夺。
- 任务带来源、理由、目标及短暂承诺时间；左后卫套上由后腰提供左侧保护。
- 候选动作比较带球、传球接球点和射门。传球考虑向前收益、接应空间、线路到达时间和指定侧偏好；近似选择保留与决策属性有关的变化。
- 传球/射门误差由执行随机流与能力、压力产生；球路与移动中的球员触球范围做步内相交检查。不会只检查步末位置而漏掉高速球穿过防守者。
- 飞行在目标时刻停止，避免超越落点后才发生虚假拦截。门将能力影响禁区内的触球范围；当前触球后直接控制，尚无完整扑救脱手/二次争夺模型。
- 近身夺球必须进入距离范围，并受独立对抗冷却限制。射门穿过球门范围内的门线时记进球，出界和进球后使用显式简化重启。
- 解释事件记录时间、参与者、战术来源、动作、候选比较、执行误差，以及接触位置和依据。
- 分领域随机状态、锁定配置、JSON检查点恢复；进行中的球路、任务和计时均保存。配置指纹用于误修改检查，不是防恶意篡改的安全签名。
- 只读回放采样；触球/进球处插入事件关键帧，比分与事件按播放游标显示，重启不插值穿越全场。
- 模拟在浏览器Worker中生成，观看和慢放不修改模拟；重新生成会终止旧Worker。

## 下一阶段与明确限制

1. 目前是合成短片段，不是完整90分钟比赛：没有半场换边、加时、点球、越位、犯规、定位球和被动换人。死球后整体回到重启阵型是显式简化规则。
2. 球员属性只使用原型输入字段，未接入真实卡牌、强化、羁绊、队长和特性。不能把这批合成结果解释成现有球员强弱。
3. 已有简单无球任务和防守响应，尚无复杂盯防交接、跑位协作、视野遮挡和完整风险评估；不能据预设名称宣称战术已经完成校准。
4. 解释记录的是代码实际比较和触球事实；候选价值不是成功概率，也不是战术因果贡献百分比。
5. 录制是有时长上限的完整帧与紧凑事件，下一阶段需要运动段、关键帧增量、任务字典及独立轨迹存储；不要写入现有联赛JSON。
6. 正式上线前仍需输入/结果适配、运行时预算、服务器Worker调度、发布游标、权限与真实赛制规则。旧引擎保持原路径。

推荐下一步：先围绕二打一、压迫封线、套上后失球等局部场景完善任务协同与首次触球/二点球，再加入完整规则；保留当前播放器作为验收工具。
