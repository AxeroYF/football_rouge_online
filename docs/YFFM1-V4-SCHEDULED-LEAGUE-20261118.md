# V4 本地联赛轮次闭环

本阶段把 V4 完整比赛接到原联赛轮次流程，仍只操作带隔离标记的本地副本。正式定时器和引擎开关保持原状。

## 流程

1. `beginRound` 检查当前待赛轮次、重复参赛和其他直播，编译整轮输入；把运行状态、赛程身份、输入、公开时钟以及调度器指定的内核指纹一起原子提交。
2. 本地调度器从持久化任务恢复入队，最多两个进程各交替生产四场。策略回退不改变已锁定任务，也不会自动重新开启未入队任务。
3. 动态预览可在录像出现前注册整轮。归档只在账户鉴权后读取，按固定公开时钟逐步发布；主队与旁观者保持不同数据权限。
4. 完整比赛已生成但尚未到公开结束时间时，调度返回 `pendingReleaseAt`，任务保留 `produced`。生产错误仍会向上报告。
5. 逐场结果绑定原 `round.fixtures`，调用原个人数据、体能、积分、门票、赞助和预测结算；跨场保存本轮新增伤停。
6. 全部比赛已公开且消费完毕后，调用原 `finishRound`，将奖励、收件箱、伤停、下一轮/赛季状态和整轮回执一并提交。下一轮重新读取已更新的球队状态编译输入。

原存储桥会核对磁盘和内存，拒绝覆盖外部变更。原子保存若在提交后抛错，则读取持久化回执确认是否已完成。重开和重复调用不会再次消费赛果或发放奖励。

## 验证内容

- JSON/分片的逐场绑定、公开时间门槛、轮末奖励、伤停、重开幂等与跨轮次输入。
- 部分入队恢复、默认关闭、已锁定任务在策略回退后继续、整轮内核指纹冲突拒绝。
- 提交前后实际终止进程，覆盖两种存储；旧伤停只扣减一次，新伤停保留。
- 连续两轮真实阵容、16场完整比赛；两种存储对比赛程、积分、个人数据、钱包、卡包和预测结算。
- 实际账户的桌面/手机动态回放，包括开播前空画面、伤退与被动换人事件、视角权限、加速、完场比分及账户撤销。

本轮真实演练暴露了伤退事件时间的浮点边界：`49.800000000000004` 与帧时间 `49.8`。按时间独立筛选会跳过中间事件。本次改为只提交连续事件前缀，等待后续画面覆盖剩余事件，不改变比赛内核或原始事件。另增加初始化目录被短暂占用时的有界重试，并保护已存在的目标目录。

## 当前边界

- 仍是显式调用的本地联赛演练，无生产定时器接入；杯赛/赛季决赛的整轮调度尚未接入。
- 动态宿主最多保留16场，旧轮次需由宿主明确移除；未提供生产录像归档与清理策略。
- 原存储核对和提交仍是同步操作。46号容量证据属于其冻结源码，不能替代当前轮次及混合业务的容量测试。
- 非中性天气及尚未支持的特性继续拒绝编译；未自动把未执行的旧引擎任务当作完赛。
- 香港云主机未连接。旧引擎、真实存档、预测V1/24样本和赔率规则保持。

验证入口：`scripts/verify-v4-scheduled-league-local.mjs`、`scripts/verify-v4-scheduled-browser.mjs`。只有新的独立验收报告成功生成后，本阶段才算冻结验收。
