# V4 本地杯赛闭环

新增显式调用的本地杯赛调度器，只接受标记副本和已验收的内核包。原杯赛定时器没有改动，正式服务不启用 V4。

## 赛程与结算

启动时锁定当前待赛事件、真实赛程 ID、双方身份、源阵容和公开时钟。联赛与杯赛的未完成 V4 事务互相排斥，其他旧引擎直播也会阻止启动。部分入队可从已提交的整轮任务继续；策略关闭不重新解释已锁定任务，也不会把未执行的旧引擎比赛当成完赛。

淘汰赛首回合允许平局。次回合检查首回合赛程及战报记录一致，按当前主客顺序带入累计比分；总比分平局进入加时和点球。决赛和瑞士轮需要胜者，杯赛联赛阶段允许平局。编译失败不会把原事件标成运行中。

完整赛果必须等到固定公开时钟允许结束后才消费。每场结果绑定真实杯赛 fixture，并调用原个人统计、体能、门票、赞助、预测和收件箱结算。新增伤停在事件元数据中累积。整批结束后，原 `completeCupEvent` 推进晋级、奖励、可用性和下一赛事，其完整状态与事件回执由原 JSON/分片存储一起提交。

崩溃恢复通过提交回执辨别已经完成的业务效果；重复调用不会再次发奖、扣减伤停或产生新比赛记录。

并发验证暴露了 Windows 在竞争独占锁时偶尔返回 `EPERM`。隔离日志现在对这类暂时占用做最多五秒的独占创建重试，仍不删除或抢占其他进程的锁；锁属主信息写入失败时禁止进入业务事务，保留现场供恢复检查。相关故障注入和实际并发恢复测试通过。

## 播放器

动态宿主从杯赛队列读取录像，仍先鉴权再访问磁盘。公开 head 仅附带赛前已知的阶段、回合和首回合累计比分，不携带本场未来结果。总比分、点球比分和晋级／夺冠提示由当前播放帧计算；回看会恢复当时的显示。切换账号或权限撤销会清空这些信息。

## 验证与边界

准备测试覆盖重叠、变更赛程、内核冲突和首回合记录不一致。两种存储各验证七个比赛日、29 场短赛的完整淘汰流程。实际终止决赛提交前后的进程，验证 JSON/分片恢复时冠亚军礼包、收件箱及旧／新增伤停只处理一次。

真实阵容完整杯赛及桌面／手机浏览器证据由 `verify-v4-cup-local.mjs`、`verify-v4-cup-browser.mjs` 生成，只有独立验收报告成功生成后才算冻结。本阶段不代表受限资源下的杯赛容量结论；50 号混合负载结论属于其冻结源码。

仍待完成联赛与杯赛交错的全赛季验证、生产定时器接入、录像保留策略和香港实机验证。赛季总决赛按现有双级联赛改革规则继续停用，不作为本次接入待启用的赛事。原联赛／瑞士轮杯赛分支保留原方法，但完整现实赛制演练以当前十六强淘汰杯赛为范围；旧赛季决赛测试包含启用旧赛制的过时预期，本阶段另运行当前分级规则测试。非中性天气和未支持特性仍按既定规则拒绝，旧引擎与真实存档保持。

完整决赛出现加时、补时及点球，录像结束时间为 8630.4 秒。最初验证脚本固定在两小时后要求结算，正确触发了等待发布；修正为使用归档真实结束时间后，从原任务恢复完成，没有改变比赛结果。全新分片副本逐轮重放验证全部 29 场。奖励流水及两条新赞助邀约的 ID 使用原墙钟生成，跨存储只对内容已逐条证明相同的新记录及明确引用作一一映射；重开后的实际 ID 仍完全一致。
