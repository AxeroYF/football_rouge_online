# V4 本地持久化调度

`versus/v4-host/dispatcher.js` 把服务端版本策略、冻结输入、后台生产和隔离业务结算接在一起。默认策略为 `off`。这里的 `canary` 是本地副本演练分支；主服务尚未接入此调度器，真实存储不会因此切换。

## 生命周期

1. 宿主提供已经验收的内核包信息和规范化比赛输入。入队检查输入指纹及实际内核文件；客户端不能通过请求启用新引擎。
2. 原子记录比赛、输入、内核路径及摘要、赛事上下文、选择结果和策略版本。重复入队返回原记录；同一比赛改变输入或上下文会被拒绝。
3. 最多两个子进程并行生产，每个进程的 Node 老生代上限为256MiB。这不是整体内存硬限额。默认最多32个未完成任务、256条比赛记录；达到上限拒绝新增，需要宿主管理归档。
4. 子进程只生成隔离战报和录像，不导入正式联赛单例。计算可以乱序完成，业务结算严格按入队顺序执行。前面的失败任务阻止后续结果越序结算，修复后需显式重试。
5. 业务状态与结算回执由隔离协调层一起原子提交；调度完成状态随后更新。若两者之间崩溃，恢复会读取原业务回执，不重复累计积分或个人统计。

`off` 的比赛记录为 `legacy`，不生成V4任务目录；实际旧引擎执行仍归现有宿主负责。`shadow` 保留旧引擎作为正式结果来源，只计算与结算隔离副本。`canary` 记录本地V4选择，并使用相同的隔离生产与结算边界；结果仍为 `settlementAllowed:false`。

## 回退、暂停与恢复

策略变更使用 `expectedRevision` 拒绝过期写入并保留历史。策略回退只改变后续新比赛；已经入队的比赛继续原输入、原内核、原上下文，重新打开调度器无需提供新的候选包配置。

`drain({signal})` 支持暂停：终止该次调度的生产子进程并等待退出。异常任务不会悄悄换回旧内核重算。调度器进程死亡时，生产子进程在私有IPC断开后退出；恢复只清理已确认进程死亡的锁。活进程的锁不能抢占。

状态文件与回执采用写临时文件、同步、原子替换。Windows 下同进程多个打开句柄共享读取与替换队列，避免高频状态读取持续占用目标文件。不同进程之间仍使用独占写入锁及有限重试。初始化的未发布暂存目录保留供检查。

## 验证与限制

`node scripts/run-tests.mjs engine-v4-dispatcher.test.js` 验证策略锁定、重复与冲突入队、队列和生产者上限、失败阻塞、暂停、提交后杀进程、生产中杀进程与已提交录像前缀保持、默认关闭及损坏记录拒绝。单元测试自行创建内核包，不依赖历史输出归档。

`node scripts/verify-v4-dispatch-local.mjs` 使用真实球队只读快照，重定向所有数据路径后运行八场完整比赛，核对原业务积分、个人出场统计、固定结算顺序、重启幂等以及回退后继续锁定版本。该验证没有施加2核/2GiB限制，不等于容量或云主机验收。

正式赛程生成、赛季推进、跨轮次重新准备体能与阵容、赛程重叠约束，以及原JSON/分片存储中的业务与回执原子提交仍需接入。当前输入由调用方准备；不能把同一旧快照直接用于后续多个赛季轮次。赛事支持联赛和杯赛，总决赛/友谊赛未接入此调度层。用户已要求暂不连接云主机。
