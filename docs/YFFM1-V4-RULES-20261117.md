# V4 第三阶段：规则与校准

版本 `4.0.0-prototype.3`，2026-11-17。独立入口仍为 `npm run dev:v4` / http://127.0.0.1:4314；已有页面刷新即可。正式 V3.3、预测 V1/24 样本及真实存档不接入此次改动。

## 规则闭环

`versus/v4/rules.js` 提供纯规则判断；`engine.js` 负责实际接触、判罚事件、死球等待、合法重启站位和恢复比赛。判罚不会直接生成进球或指定二点球赢家。

### 越位

队友触球时记录球、倒数第二名对手和本方候选人的位置条件，取球与防线中更靠近对方球门的限制，并排除本方半场和齐平位置。站在越位位置本身不吹停，实际触球或近身争抢影响对手后才处罚，地点采用参与地点，恢复为间接任意球。

角球、球门球和界外球的直接接球不建立越位候选；任意球没有这一豁免。扑救和折射保留旧阶段。对手控制球，以及低相对速度、良好朝向且有空间的主动处理球，可以清除此前阶段，即使该次处理没能完全停稳。这个主动处理机会是模型的可解释近似，不等同于真人裁判的全部主观判断。

任务和候选传球也会考虑越位线，减少明知越位仍传球的行为。规则本身继续独立检查，不能依赖战术规划始终合法。

依据：[IFAB Law 11](https://www.theifab.com/laws/latest/offside/)。当前采用球员点坐标，不建模身体部位、门将视线遮挡、出场球员回场及门柱反弹。

### 犯规与纪律

持球者与防守者进入实际近身争抢范围后，结合抢断能力、相对速度和身后接近判断接触犯规。解释保留概率、随机判定和动作程度；疏忽、鲁莽和过度力量分别进入无牌、黄牌或红牌路径。禁区接触犯规判点球，禁区外判直接任意球。

明显进球机会的近似判断考虑距门距离、方向和其他防守者；本模型产生的争抢均为试图争球，禁区内点球场景适用相应减轻处罚。两黄变红后球员保留在名单和回放中，但停止移动、任务、触球与决策；门将被罚下时由场上球员接管，未引入主动换人。一方不足七人终止独立模拟，不写正式联赛赛果。

依据：[IFAB Law 12](https://www.theifab.com/laws/latest/fouls-and-misconduct/)。目前即时鸣哨，没有有利进攻、手球、无球拉拽、假摔、争议复核或门将持球超时模型。红黄牌和犯规频次尚未进行真实联赛拟合。

### 定位球

七类重启已区分：中圈开球、界外球、球门球、角球、直接任意球、间接任意球、点球。

- 出边线由最后触球队的对方掷界外球；出底线根据最后触球与防守方向选择角球或球门球。
- 初始开球和进球后开球均执行合法半场与距离站位，并实际踢出球，不能先带球。
- 任意球采用事发地点及球门区位置修正，恢复前对手保持规定距离；界外球采用两米距离。
- 点球落在十一米点，守门员在门线上，其余队员在禁区外、球后且满足距离要求。
- 主罚后球实际飞行，门将和球员照常参与触球；短角球采用地面传球，不凭空生成高球结果。
- 主罚者在其他球员触球前再次碰球，判间接任意球；间接任意球和界外球不能直接进对方球门，所有定位球不能直接形成乌龙进球。

站位重置有明确重启序号，播放器禁止跨重置插值。准备时间为原型参数，不模拟拖延比赛、抢先进入、假动作或重罚争议；没有完整三人墙战术、高球、门框碰撞和手部动作。

依据：[IFAB Law 13](https://www.theifab.com/laws/latest/free-kicks/)、[Law 14](https://www.theifab.com/laws/latest/the-penalty-kick/)、[Law 15](https://www.theifab.com/laws/latest/the-throw-in/)。

## 可解释回放

新增越位、近身犯规、直接任意球、角球和点球观察场景，总计十一种。事件分类增加“判罚与定位球”；越位事件能显示出球时的越位线、球与倒数第二名对手坐标。犯规展示相对速度、禁区归属与明显进球机会判断。

已播放统计只计算当前时间之前的传球、接球失误、犯规与越位。罚下球员不再绘制为场上圆点，但仍可从名单查看纪律记录。可调速、关键片段慢放、协作任务和二点球解释继续保留。

## 校准方法

脚本 `scripts/calibrate-v4.mjs` 使用四种战术的全部十六种对阵组合，固定训练种子与独立验证种子，保存每段比分、传球、接球和判罚统计。参数改变后保留中间报告，不根据验证结果强行指定赛果。

传球成功率定义为队友直接控制的传球数 / 实际传球次数；接球失误率定义为队友首次接触传球时的失控次数 / 该类首次接触总次数，不把未能碰到的传球、对方拦截或二点球重复触球混入分母。

原型工程区间为传球成功率 70–90%、上述接球失误率 2–12%、十分钟平均进球 0.15–0.65。90分钟连续诊断额外检查平均总进球 1.8–4、零进球比例不高于25%、六球及以上比例不高于15%。这些是本阶段的工程验收目标，不宣称源自某个真实联赛的拟合。

调整作用于实际机制：提高线路安全和接应空间权重、降低无条件向前传的收益、尊重越位线、鼓励有空间时带球推进；压迫强度不再过度推高整条后防线，常规封线与压迫保护不抽走中卫盯防；普通来球控制与射门扑救采用不同难度；射门误差受距离和能力影响，门将触球范围表现扑救覆盖；降低原型中过快的体能消耗。没有按预定总进球截断比赛或修改已产生比分。

十分钟窗口用于与第二阶段同种子对照。90分钟诊断实际连续推进5400秒并统计终场比分，不靠短片段乘九推算比分分布；但它尚无半场、交换场地、补时或完整比赛赛制。浏览器仍只提供3/5/10分钟回放，长时批量诊断关闭完整帧录制。

校准报告记录输入种子、每场结果、统计分母、工程门槛、源文件哈希及本机工作线程数量。验证是本机未限资源模拟，不是香港2核2GB容量验收。完整调试轨迹仍较大，不能直接加入联赛JSON。

以下四组报告均通过各自全部预设门槛，最终验证种子为此前未用于调参的 `validation-r2` / `validation90-r2`。训练集与验证集的种子相互独立；失败的中间报告保留，包括 `validation90-tail-failed.json`。

同一验证集有37张红牌、平均每场约3583次传球，这些频次尚不适合作为正式比赛目标，后续必须分别校准犯规/纪律与动作节奏。当前完成的是所列三项指标的工程校准，不代表全部足球统计已经合理。

48项V4测试、16项旧引擎/回放定向测试、48段180秒组合、11个专项场景恢复一致性、真实Chrome桌面和390px手机检查通过。600秒完整录制3382帧、1228事件，调试JSON 37,883,345字节。汇总检查还验证四份校准报告的源码哈希和本轮保护文件未变。
