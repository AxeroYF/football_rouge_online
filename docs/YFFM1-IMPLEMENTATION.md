# YFFM1 第一轮优化交付 · 2026-11-03

本地分支 `codex/yffm1`，来源为 S4 最终源码 `887df19`。本轮实现名称统一、数据可靠性、配置收敛、静态资源性能和测试工具整理。没有修改比赛平衡参数、清空账号或部署正式服务器。

## 已实施

- 页面、后台、电视台客户端、离线启动器显示名及工程包名统一为 YFFM1；新增标准入口 `server.mjs`、`npm start`、`npm run dev` 和 `.env.example`。旧 API、卡片 ID、存档路径、浏览器登录键及应用标识保留兼容。
- 账号存储抽出 `JsonAccountRepository`：损坏文件停止加载；唯一临时文件、fsync、原子替换；保存失败恢复内存账号和阵容码。注册、改密、重开存档和故障恢复有专项测试。
- 内容配置抽出串行 JSON 写入器：启动迁移与后台更新按顺序落盘，每次保存捕获独立快照；主文件与上一版备份均通过临时文件替换，修复并发写入导致的文件锁问题。
- 战术保存与导入复用 `assertLineupRevision`；导入递增版本，前端/API 显式传入方案 ID 与 revision，拒绝旧请求覆盖新结果。
- 引擎配置由 `src/runtime-config.js` 统一解析，支持 YFFM 与旧 YDL 环境变量；状态接口与联赛使用同一选择。生产或非回环地址启动要求显式管理员密码，开发及离线模式保留明确的本地配置。
- 静态资源新增 16 MiB 缓存，按 size/mtime/ctime 失效；并发请求共用读取与异步压缩；正确处理 Accept-Encoding、gzip 禁用、ETag/304、HEAD 和只读方法。
- 球员能力预览抽出纯函数模块，避免 UI 全局状态影响独立验证；补齐缺失的 AI 徽章；修复浅色主题建队标题的对比度。
- 自动发现当前 `test/` 中的测试，按文件隔离运行数据并保存日志；保留长跑完整入口，提供快速入口；增加语法检查、浏览器审阅与静态资源微基准工具。

## 验证

- Node.js 24.22.1，Windows 本地。
- 快速回归：59 个文件、499 项检查全部通过，无失败/超时。该入口明确排除 7 个长跑测试文件，不等于完整测试全绿。
- 260 个 JS/MJS/CJS 模块语法检查通过；`git diff --check` 通过。
- 真服务 HTTP 测试通过：品牌、默认 V2 配置、gzip/identity 内容一致、304、HEAD、405、AI 资源、注册及登录。
- Chrome：1440×1000、390×844；注册和进入联赛成功，无 pageerror 和页面横向溢出；截图在 `outputs/browser-review/`。
- 静态资源本地微基准：50 次读取/压缩约 403 ms，预热缓存后 50 次 get 约 0.043 ms。测量不包含 HTTP、stat 和网络，不代表全服 CPU、响应时间或容量的同比提升。

日志输出在 `outputs/tests/`；评估时期材料仍在 `.assessment/`。测试账号和临时数据没有进入生产存档。

后续针对页面重建、强化选卡、阵容松手和直播更新的性能修改、523 张卡片的测量与显示对照见 [前端性能记录](YFFM1-PERFORMANCE.md)。前台显示模板和业务规则保持原样。

## 测试修订依据

旧测试有部分断言与归档代码不一致。本轮保留现有规则：球员目录排除 X 球员、正式卡池包含新增特性、固定体力为 94、身高特性为 -5 cm、雨天增益为 12%、落后时不再触发已移除的顺风战士减益。使用这些已存在规则更新预期，没有调整规则使测试通过。

伤退职责测试原本以固定 RNG 同时强制触发群架，导致目标先被红牌罚下；现在仅禁用该场景中的群架事件，保持伤病换人的验证。世界杯功能在当前源码中仍然存在，取消了“应被移除”的过期断言。X 球员测试通过正常保存方案注册首发，避免只改队伍临时字段而遗漏持久方案。

UI 结构检查同步到有效的事件监听边界、组件容器及新预览模块，取消对变量名、固定函数调用次数和过期文案的依赖；注册/登录/进入联赛另有真实浏览器检查。

## 仍需继续验证

完整 `npm test` 尚未全绿。较早完整批次中，`league.test.js`、`season-simulation.test.js` 超过每文件 180 秒；`match-engine-v2.test.js` 和 `ydl-league-engine-v2.test.js` 还有历史场景/版本预期失败。长跑结果不能计入本轮“全部通过”；后续应针对这些文件拆分场景、测量计算热点，并确认旧版本断言与当前动态引擎的契约。根目录历史副本和根目录 12 个旧测试保留为来源资料，没有并入当前测试发现。

本轮尚未对 12,000 行联赛服务和约 8,000 行主页面做全面分域重写；已先抽出存储、版本、配置、缓存和预览边界。后续优先细化赛事结算/资产交易边界，再建立真实大存档和多客户端性能场景。

Windows/macOS/Android 的名称与构建源文件已更新，未生成或发布新的安装包。Windows 离线包仍依赖私有种子资料，macOS 签名/DMG 需要对应平台验证。Node 22 的 CI 配置是待运行的验证入口，不能当作已经通过。
