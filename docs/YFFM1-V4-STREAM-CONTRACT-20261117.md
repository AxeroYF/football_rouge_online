# V4 实时回放协议预备实现

prototype.8 内核已完成本地联合验收，冻结源码和证据见交接文件34。当前继续宿主接入：独立发布服务及现有账号预览页支持真实球队只读录像；正式比赛仍使用原引擎。以下状态更新于 2026-11-18，宿主阶段证据与内核验收分开记录。

## 协议与权限边界

`versus/v4-stream/codec.js` 将呈现状态编码为每包独立关键帧、路径字典与增量。坐标和速度保留两位小数，朝向保留三位小数；原模拟状态不变，不能拿呈现数据恢复比赛引擎。

`publisher.js` 的 `publishUntil` 由可信服务端调用，不能倒退或超过已生成帧。`read` 只接受已发布范围内的恢复游标和批量大小，没有推进比赛的播放速度参数。服务端发布时钟和客户端回看、慢放、追赶的游标必须分离。

每包绑定比赛 ID、引擎版本、观察方、起止帧和事件游标。关键帧支持独立解码；客户端拒绝版本不一致、缺包、冲突关键帧、越过发布时间的帧与事件。重复传输不重复插入。

默认观众仅获得公开空间状态和实际比赛事件。本方观察视图可增加本方任务、体能和决策解释；对方任务、战术预案、候选评分和随机数不发布。隐藏的事件可跳过 ID，但不可通过读取恢复游标取得其内容。

**账号到 `ownerSide` 的绑定必须由服务端认证后完成，不能信任 URL 参数。** `http-service.js` 提供 `GET /v4/matches/:id/head` 与 `/segments/:index`。宿主通过既有 `rooms.account` 校验账号，再根据当前球队归属确定私有视角；观众由服务端清单授权。查询参数不能改变观察方、发布时间或模拟速度；未发布片段返回 425，无权访问返回 403。

`devtool/server.js` 默认不开启这些路由。只有显式设置 `YDL_V4_STREAM_MANIFEST` 才加载 `shadow-preview` 清单。配置必须匹配归档的输入、版本和源码指纹，路径限于清单目录之内。归档读取发生在认证、限流和并发检查之后。预览只读，不启动模拟，不调用正式结算。

本机演练服务的 `/lab-sessions` 仅发放三种演练身份，不能部署为正式认证入口。`npm run dev:v4-stream` 只监听 `127.0.0.1:4315`，不导入正式联赛服务、不写入真实存档。

## 录制、磁盘与播放器

`producer.js` 在独立 worker 内分段推进比赛。`archive.js` 为每段生成观众、主队、客队三份独立裁剪的 gzip 文件与 SHA-256；清单原子提交成功后才释放已提交帧和事件，保留最后一帧作为后续录制基点。观众端不取得引擎检查点。归档缓存有上限，发布时钟由服务端独立持有，重新打开归档默认不发布任何片段。

清单读取串行验证历史，防止并发读完成顺序不同导致误判历史回退。Windows 暂时性文件共享冲突采用有限重试，替换成功前保留旧已提交清单；磁盘空间等其他错误直接报错。锁定生产者可从原输入确定性重演，核对全部已提交分块并复用内容一致的未提交文件；冲突内容拒绝恢复。`shadow-job.js` 把录像与个人战报串为单写入任务，实际子进程终止后的恢复已验证。不是通过小圆点帧恢复引擎，也不是快速跳转到检查点继续录像。

`playback.js` 只推进画面时间，不导入引擎。支持 0.5–64 倍速、关键射门慢放、暂停、已发布范围内回看、追赶直播以及断线保留缓存后重连；关键帧可独立解码，缓存帧与事件数量有界。简易网页提供小圆点、比分、时钟、球员选择和本方任务解释，已覆盖桌面与手机布局。

新增 `/v4-preview/?match=比赛ID` 使用同源游戏登录信息，无演练身份切换器、无 URL 凭证。账号被拒绝或另一标签页更换登录状态时，清空画面和私有任务。静态路由精确列出呈现模块，不公开引擎、生产者、归档目录或发布配置。宿主预览每半秒获取一次更新、最多预读60秒已发布画面；每次最多追加4段，缓存仍有界。每账号每分钟600请求支持64倍速回看。首轮十人快放暴露4并发不足后，宿主总并发上限调整为16。

`initialize-job.js` 在独立暂存目录备齐输入锁定、隔离日志和空归档，最后一次性重命名发布任务目录。发布前异常或杀进程不会留下可见的半成品任务；暂存目录保留以便检查，不自动删除文件。并发初始化只有一个能发布。旧版本已经存在的损坏半成品仍拒绝打开，不会静默修改。

- `scripts/measure-v4-stream.mjs`：完整合成比赛逐包编码、独立 gzip、JSON 解码、呈现状态逐帧核对。报告区分原始内部记录、权限裁剪后的记录、增量 JSON 与 gzip 传输大小。
- `outputs/v4-stream-20261117/full-match-size.json` 保存测量，不能当作香港云主机容量验收。
- `test/engine-v4-archive.test.js` 验证有界录制后的状态一致、磁盘回放逐帧一致、发布边界及损坏检测；`engine-v4-playback.test.js`、`engine-v4-stream-http.test.js` 验证播放时间与权限。
- `engine-v4-atomic-file.test.js` 覆盖暂时性错误重试、重试上限以及不可重试错误。内核冻结时流式测试13项通过；宿主阶段另增加64倍速预读测试。
- `scripts/verify-v4-stream-lab.mjs [--real]` 检查浏览器内的变速、暂停、回看、断线恢复、追赶、身份视图与手机宽度。旧报告只证明其记录的源码，最终交付需与候选源码哈希核对。
- `scripts/benchmark-v4-stream-local.mjs` 的120秒受限本地验证已通过：两个逻辑核、2GiB Job Object、10名观看者、2个并行生产者、4场真实阵容完整比赛全部完成，head/segment P95为67.54/83.14毫秒，RSS约257MiB。证据在 `outputs/v4-stream-capacity-20261118/iteration14/capacity.json`。这不是新宿主600请求额度下的10人同时64倍速测试，也不是香港云主机验收。
- 新宿主快放容量另见 `outputs/v4-host-capacity-20261118/iteration2/capacity.json`：两逻辑核/2GiB，10个实际隔离账号同时64倍速回看，均约103.14秒完成6600秒录像，零429/客户端错误，head/segment P95为63.18/73.71ms，RSS约111MiB。客户端解码不占宿主资源限制；此项使用已完成归档，不同时生产比赛。首轮失败报告保留在其上一级目录。

## 本地预览准备

`node scripts/create-v4-shadow-preview.mjs --output=outputs/自定义新目录 --fixture=比赛ID --seed=固定种子 --rate=8`

默认选择只读快照的前两支球队，也可指定 `--home=球队ID --away=球队ID`。使用冻结内核创建完整比赛，输出 `preview.json` 和观看路径，不启动服务器、不设置环境变量、不修改存档。默认只允许参赛球队账号；`--public=true` 才允许其他已登录账号观看公开视图。开播时间可用 `--start-at=ISO日期` 指定。输入和结算日志是服务端私有资料，不能作为静态目录发布。

## 尚待第九阶段落地

隔离结算由 `shadow-settlement.js` 统一协调：锁定比赛输入、赛事上下文和首次结算时间，调用原业务消费函数后核对个人累计统计与唯一比赛记录，再原子提交业务状态和回执。并发重试及提交前后实际杀进程的恢复均验证只结算一次。该协调层只接受隔离日志，不连接正式存储。

双方持有同一球员卡时，V4 的点球受益统计按球队区分。`league-service.js` 的联赛、杯赛和总决赛消费处共三个表达式增加 V4 schema 分支，旧战报仍执行原表达式。保护检查逐字节核对这三个变更；其余七个受保护文件（含真实存档、旧引擎和预测）保持原哈希。总决赛旧测试的39项中28项既有失败，在冻结旧源码与当前源码下逐项一致；这是差异回归一致，不是该旧测试全通过。

当前源码的容量复验见 `outputs/v4-host-capacity-20261118/iteration3/capacity.json`：十个隔离账号均完成64倍速播放，无429或客户端错误，head/segment P95为61.11/69.72ms，峰值RSS约111MiB；资源范围与上一轮相同。

正式联赛调度器的版本选择及事务结算桥、香港实机验证仍需后续处理。球员战报已在原联赛/杯赛结算逻辑的复制状态中验证，但这不代表正式事务已接线；所有 V4 结果仍标记 `settlementAllowed:false`。真实存档保持不变，用户要求暂不连接云主机。
