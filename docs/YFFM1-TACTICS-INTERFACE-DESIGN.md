# YFFM1 战术界面、心态与预期打法图设计

日期：2026-11-10。基于当前本地 V3 引擎与《战术模块扩展规划》。本文为拟定方案，参数表属于候选配置，尚未经过平衡验证。

2026-11-11 实施更新：按后续要求保留原战术板与替补席逻辑，改用“上方大阵型板/替补席，下方原则/雷达”布局，球场沿用原比例。独立战术原则和真实阵容雷达已落地，详见 [实施记录](YFFM1-TACTICS-IMPLEMENTATION.md)。本文后面的三列方案和“尚未实施”等描述保留为原设计历史，实际交付以实施记录为准。

## 已确定的方向

1. 电脑端优先，采用此前选定的“专业经理桌面”方向；手机端使用相同的信息和术语。
2. 以“比赛心态 + 四类战术原则”为主干，替代一个打法承担组织、防守、转换、对抗全部含义的设计。
3. 增加六方向“预期打法”雷达图，结合当前首发、站位、职责和战术配置生成静态估计。
4. 按用户要求移除原球员位置/阵容适配度、战术适配度展示。新图不复用这两个总分，不设置综合适配分、星级或面积排名。
5. 此次已先移除旧界面相应展示；本文件中的新界面、心态解析和雷达计算仍为后续实施方案。

## 现状中需要解决的问题

- 心态里的“防守反击”和打法里的“防守反击”重名；“全力防守”又与“摆大巴”混合了心态和防守区块。
- `syncLeagueTacticalPresetControls` 在切换心态或旧打法时重建八个主要滑条，会覆盖玩家微调。
- 现有心态预设同时改变冒险、节奏、纵深、宽度、防线、压迫、紧凑、反击和比赛控制，不能直接将其改名后声称这些选择互相独立。
- 分拆战术已有底层基础，但界面草稿与联赛保存尚不能完整保留所有分拆字段；已有完整数值覆盖时，原则变化也可能不改变实际参数。
- 低位防守当前会把有效心态限制至 52；部分远射、防守身份判断还依赖旧心态/打法标签。新版本需要明确归属和兼容规则。
- 默认、领先、落后三套详细表单同时展开，首发、替补、职责、触发节点和辅助操作争夺空间。

## 比赛心态

### 命名与语义

心态回答“球队愿意为进攻承担多少风险”。它影响整体前压、跑动投入与引擎现有的机会投入计算，不再自动替玩家选择长传、反击或压迫方式。

| 新名称 | 旧标识 | 初始沿用的心态值 | 玩家看到的说明 |
| --- | --- | --- | --- |
| 谨慎 | parkBus | 20 | 优先保持结构，减少前压和冒险投入 |
| 稳健 | defensive | 34 | 控制风险，保留适度的向前支援 |
| 均衡 | balanced | 50 | 在前压与保护之间保持常规投入 |
| 积极 | positive | 66 | 增加向前支援，接受更多转换风险 |
| 全力进攻 | allOutAttack | 92 | 最大限度争取进攻，承担较高消耗与身后风险 |

五档用连续排列的按钮呈现，显示当前选择的一句说明。暂不增加七档、独立“进攻强度分”或额外全队属性奖励。上述数值沿用现有标量，不能据此承诺新组合与旧版结果相同。

### 切换规则

- 在新模型下，修改心态只改变心态标量和其实际模拟后果，不重置组织、防守区块、转换、对抗、职责和手动微调。
- 不把积极等同于快传或高位；允许积极短传、稳健长传、谨慎控球等组合。
- 第一版保留当前低位防守的冒险限制：低位时积极/全力进攻不可选，并在按钮附近解释原因。若从积极/全力切到低位，选项预先标注“同时调整为均衡”，执行后提供一次撤销，绝不显示积极却静默按 52 执行。
- 历史方案中已有被限制的组合先保留旧解析及真实有效值，明确标为历史方案；只有显式应用新版原则/预设时才转换，不能加载即改比赛结果。
- 若以后允许“低位起守 + 高风险进攻”，应把进攻冒险与防守结构进一步拆开并重新平衡，再解除限制。

## 四类战术原则

| 原则 | 选项 | 负责的含义 |
| --- | --- | --- |
| 组织方式 | 均衡组织 / 短传控制 / 快速纵向 / 边路展开 / 直接长传 | 阵地进攻的主要推进方式与路线选择 |
| 防守区块 | 高位 / 中位 / 低位 | 从哪里建立防守与施压，和阵型覆盖结构 |
| 得球策略 | 稳住球权 / 选择性反击 / 立即反击 | 球权转换后的第一选择 |
| 对抗强度 | 谨慎 / 正常 / 强硬 | 对抗决策及犯规、黄红牌风险，不直接赠送压迫能力 |

每组显示选项、当前说明和一条具体代价。选项不预设“克制某打法即增加胜率”的固定关系。

### 新版参数归属草案

为避免同一效果反复叠加，新方案以固定基线和模块建议值编译。八个旧参数不再全部以心态预设为起点。以下为借用当前量级拟定的第一组候选值，实施后需要统一校准。

| 组织方式 | 节奏 | 传球纵深 | 进攻宽度 |
| --- | ---: | ---: | ---: |
| 均衡组织 | 50 | 50 | 50 |
| 短传控制 | 42 | 28 | 46 |
| 快速纵向 | 59 | 65 | 50 |
| 边路展开 | 55 | 55 | 80 |
| 直接长传 | 57 | 80 | 56 |

| 防守区块 | 防线高度 | 压迫强度 | 阵型紧凑 |
| --- | ---: | ---: | ---: |
| 高位 | 72 | 82 | 67 |
| 中位 | 50 | 50 | 55 |
| 低位 | 30 | 34 | 73 |

- 得球策略负责反击倾向，候选值为 32 / 50 / 70；不再通过全局节奏和纵深的额外加法改变整场阵地组织。已有转换事件与风格身份也应读取独立策略。
- 对抗强度负责对抗事件，不再沿用强硬风格对全局节奏、纵深、紧凑和压迫的混合加法。
- 原“比赛控制”不作为主界面独立滑条；当前 `timeWasting` 先留在兼容计算中，新模型由机会选择等明确定义的指令生成。查看有效参数时解释为推进耐心/进攻投入相关参数，不能描述为真实消耗剩余时间。
- 旧攻防细节保留：主攻方向、机会选择、远射倾向、传中倾向；防守宽度、重点防守方向、盯人方式、防线策略。
- 基础视图按上述原则和细节组织；高级微调提供七个可调参数。数值只在高级视图或焦点说明中出现，避免基本视图重复放置同一参数的下拉框与滑条。

### 预设、原则和微调之间的关系

1. 快捷预设仅填写心态和四原则，不是额外的一层持续加成。
2. 切换某个原则时，只更新该原则负责的建议参数，清除其对应的手动覆盖；与其他原则有关的微调保留。界面显示本次改动并允许撤销。
3. 切换心态不清除任何手动覆盖；低位约束是上文明确说明的例外。
4. 手动改值后，在所属原则旁显示“已微调”；摘要和雷达均读取最终有效参数，不能仅依据原则名称推断。
5. 预设应用不改首发、站位、职责、队长、触发节点和已有详细指令。详细指令仍影响结果时，预设旁显示“含自定义指令”。
6. 解析顺序统一为“固定基线 → 心态标量与原则建议 → 详细指令 → 明确的手动覆盖 → 有效性与引擎限制”。各阶段不得重复加入旧 style 加成。
7. 前台预览、服务端保存、比赛、训练和镜像使用同一解析器；保存意图配置与手动覆盖，不把整套自动生成值伪装成手动设置。

## 页面结构

### 桌面

- 顶部：阵容方案与赛事适用范围；默认/领先/落后预案切换；保存状态。一次只编辑一个预案，其站位、职责和原则同步切换。
- 左侧约 32%：首发阵型板；基本/进攻/防守落位预览；点击球员查看能力、职责及调整选单；替补名单位于下方或独立抽屉。
- 中部约 40%：心态 → 四类原则 → 有球/无球详细指令 → 折叠的高级微调。
- 右侧约 28%：预期打法图 → 选中方向的依据、限制与具体取舍。
- 队长、导入导出、镜像、训练等低频操作集中到工具菜单，不挤占原则设置首屏。
- 首发轮换阈值移动到阵容管理，改名“赛前轮换体力线”；与未来赛中换人分开。
- 保留自动识别阵型、阵型合法性及缺门将等必要提示。移除原适配分数条、位置适配计数及其颜色编码。

### 响应式与操作

- 大屏采用三列；中等屏将阵型板放到下方或可切换区域，原则与雷达并列；窄屏改为“阵型 / 指令 / 预期打法”三个页签。实际断点按可用内容宽度决定，不能固定三列造成横向溢出。
- 手机保留顶部预案切换；当前指令的解释与预计影响就近显示，不依赖悬浮。
- 图形支持点击/触摸；方向选择同时提供原生选单，键盘和读屏可操作。
- 只有渲染和预览可以本地即时发生。失败的保存必须提示重试；雷达标明“当前草稿”或“已保存方案”，不能将未保存内容误称比赛将采用的配置。
- 阵型预览是投影，不冒充实时比赛跑位；不在每次拖动时运行完整比赛。

## 六方向预期打法图

### 展示口径

主图使用“预期打法”名称，展示当前阵容在当前预案下预计倾向哪些足球行为。默认一条当前轮廓，可选与本次进入编辑器时的基准方案比较。

原先讨论的“战术倾向 + 阵容支撑”两项作为内部计算与文字解释的来源，不再单独画成两个适配评价图层，以落实用户移除旧适配展示的要求。比较层只表示“修改前 / 当前”，不表示理想上限。

| 方向 | 指令来源 | 需要读取的球员能力 | 需要读取的结构 |
| --- | --- | --- | --- |
| 控球组织 | 短传、节奏、耐心、接应职责 | 传球、停球、视野、决策、冷静 | 中后场接应覆盖、连接距离、孤立接球点 |
| 纵向推进 | 纵向/长传、节奏、前插职责 | 传球、视野、速度、无球、停球 | 纵向连接、前场接球点与中场脱节情况 |
| 边路展开 | 宽度、主攻方向、传中、边路职责 | 传中、盘带、速度、决策 | 边路宽度、套边/内切分工、禁区接应 |
| 前场压迫 | 高位、压迫、防线、压迫职责 | 耐力、投入、速度、抢断、决策 | 前后线距离、邻近协防、身后保护 |
| 防线保护 | 防守区块、紧凑、留守、保守心态 | 站位、盯人、抢断、力量、速度 | 中路与纵深覆盖、留守结构、门前保护 |
| 转换反击 | 得球策略、前场接应、纵深 | 加速、速度、无球、传球、决策 | 可用出球点、纵向通道、向前支援与留守的平衡 |

“身体对抗、禁区争顶、远射”等先列入方向详情及球员能力依据，避免第一版扩张成十余轴而难以阅读。它们可在后续独立的阵容能力分析中展开。

### 计算设计

1. 从最终有效战术参数、职责和指令计算各方向的意图强度。
2. 从当前首发的有效属性和相关位置参与者计算该方向的能力基础。替补不直接平均进球队方向；赛前轮换实际改变首发后再重新计算。
3. 使用现有分区/阶段投影提取对应方向的空间结构，不仅依据阵型名字判断。无球、防守与转换使用相应阶段，不能全部套在一张基础站位图上。
4. 用球员能力、职责动作及结构约束意图强度，得到方向指数；不读取旧 `calculateV2TacticalFit` 总分，也不将主/副位置人数换算成新总分。
5. 第一版建议采用“意图 × 有界的能力与结构支撑系数”。各方向独立、固定 0–100 显示范围，不归一成比赛时间或球权占比。权重、映射和饱和曲线必须另行校准并版本化，不在本方案里声称已完成预测模型。
6. 有效属性、体力、特性、默契、羁绊和位置规则沿用引擎的快照口径，只应用一次。不得将已经结算过的属性再乘一次同类加成/惩罚。
7. 不使用对手资料时，只是己方静态预期，不能称为预计控球率、射门数、xG、成功率或胜率；天气和裁判尚未确定时也不填造其影响。
8. 比较基准固定为编辑器本次进入/切换方案时的快照。切换默认/领先/落后预案时分别保存基准，同一份首发对比同一预案；若首发也变了，说明比较包含阵容变化。
9. 属性和结构输入不足时显示“信息不足”，不能补成 50。非法阵型时停止生成有效预测，并保留具体的阵型提示。
10. 不计算雷达面积、不提供总分，不暗示所有轴越大越好。高压迫可能伴随防线保护下降；控球与纵向也是不同选择。

### 方向详情与交互

- 改心态、原则、职责、站位或首发后更新图形；拖动中节流，落点后计算完整结果。
- 点击方向显示三类内容：当前侧重的来源、阵容/结构的具体限制、可执行的调整。
- 例：“前场压迫”：高位防守和较高压迫带来高意图；前后线距离大、前场体力不足会限制持续执行；建议先改善前后衔接或减少持续压迫。
- 例：“边路展开”：宽度充足，但边路接应和禁区落点人数不足；提示职责分工和接应，不给出“战术适配 62 分”。
- 只解释配置变化的预期方向，不保证单场必然增加射门或减少失球。训练/比赛后可以另做真实行为对照，不能拿静态图代替实际统计。
- 生产界面的数字以整数为主，方向详情提供数值和基准差；图上不堆 12 个数字或只依赖颜色。

## 保存、兼容与引擎接入

- 新方案使用明确的 `tacticalModelVersion`，保存五档心态、四原则、细节、职责和手动覆盖来源。旧 `tactic` 标识保留用于历史兼容与特性条件，不能把心态直接删除。
- 旧方案加载先冻结旧解析后的有效值和旧身份，不以新预设猜测还原原作者意图。首次转换前显示会改动的原则和参数；历史报告继续按原快照读取。
- 对 `styleIdentity`、远射中的旧心态=低位判断、对抗事件、阶段路线、压迫回收逐项确定所属原则；新方案不叠加一个旧 style 和四个新原则。
- `applyTacticalPlan` 的变化识别必须包含新字段/配置修订，不能只比较预案名、tactic 和 style。
- 前台草稿、自动保存、联赛白名单、阵容方案、分享导入导出、比赛快照、存续恢复、AI/镜像训练和 worker 协议一同贯通。
- 雷达服务返回输入修订与模型版本；异步结果过期时丢弃，防止快速改配置后旧结果覆盖新图。缓存只依赖当前快照与规则版本，不写入高频比赛日志。
- 首期不包含新的反抢决策、自由跑位、常规赛中换人或真实时间消耗。转换页先展示已支持的得球策略，后续模块接入时沿用这个入口，不摆放无效开关。

## 实施顺序和验收

1. 已先执行：移除原阵容/战术适配展示、位置适配统计和颜色、自动指导弹窗中的适配数值，以及直播/战报策略摘要里的适配百分比；保留选人和模拟规则。
