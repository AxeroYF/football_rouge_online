# YFFM1 V3.0 第一轮实施与验证

完成记录：2026-11-04。目标是减少同条件下的偶然波动，让玩家的应对和空间布置产生可解释的收益，同时保留球员能力与培养价值。本轮修改比赛计算和版本标识，前台页面布局、控件及操作方式沿用现有实现。

## 实际运行版本

| 字段 | 当前新比赛 |
| --- | --- |
| 配置选择 | `v3` |
| `engineVersion` | `3.0.0` |
| `engineProfile` | `v3.0-tactical-control.1` |
| `modelVersion` | `match-engine-v3.0` |
| 控球链 | `possession-chain-v3.0` |
| 空间模型 | `spatial-v3.0-tactical.1` |
| 动态阵型 | `dynamic-shape-v3.0-stable.1`，stable 位移混合仍为 0.15 |

联赛、杯赛和友谊赛的默认选择均为 V3；AI 训练和镜像批量比赛使用 V3。配置接口 `/api/versus/config`、比赛广播、最终记录和 Worker 返回均带实际版本。新 Worker 协议为 `v3.0-tactical-control-r1`，旧 Worker 需要更新代码后重新连接。

`YFFM_MATCH_ENGINE=v2` 可显式使用 V2.1，`v1` 仍保留为旧引擎入口；竞猜内部的低成本定价抽样仍使用 V1。已有环境变量覆盖继续生效。旧比赛记录保留其原版本，本轮没有将历史比赛重算为 V3。

共享实现继续位于 `versus/v2/`，V3 的入口和配置位于 `versus/v3/`。存档/广播中内部 `version:2` 是沿用的数据格式版本，实际比赛版本应读取 `engineVersion`、`engineProfile`。这一兼容安排避免更换 API、存档标识或前台数据结构。

## 已实施

### 降低结果波动

新增按比赛种子和事件通道划分的混合分组抽样。每个结构化分组含 12 个打乱顺序的区间，并混合独立随机样本：阶段结果的分组比例为 0.65，进球为 0.75。它降低短期连续极端结果的频率；具体概率仍由当前的能力、战术、空间和局势计算决定。

采样器只读取种子、事件通道、计数和配置，不读取领先落后或队伍强弱。单元测试验证同种子下即使交换比分与强弱，采样序列仍然一致；计数可序列化，保存后继续的采样结果可复现。

射门先按原来的进球概率采样，再用条件概率补足未进球时的射正。这保持概率关系，并使每次射门都进入同一进球通道，避免扑救链提前分支让抽样规律失效。V2 分支继续采用原来的抽样流程。

V3 同时下调了部分低可控独立事件：黑哨基础概率 0.02→0.005，乌龙 0.009→0.004，群架基础概率 0.0063→0.003。粗野风格、天气、纪律与相关特性仍按各自规则参与。

### 提升战术指令和空间的作用

- 防守方向和宽度在真正的阶段动态投影前生效，完整保留偏移，避免被 0.15 位移混合缩小或在已解析位置的投影中丢失。防守预览共用同一处理函数。
- 攻击方向偏好适度加强，路线选择仍同时考虑连接、控制、可利用空间与推进条件。
- 降低各阶段 `execution` 项权重，将部分权重移向连接、空间、局部人数或推进条件；能力差在单次执行项中的除数从 150 到 200。原有能力上限和前台展示数值保持原样。
- 中场带和中央带采用平滑贡献，缓和原先跨越坐标边界就突然改变人数惩罚的问题。阵容合法性和位置分类的硬约束仍保留。
- V3 移除“双后腰 + LM/AM/RM + 单中锋”这一特定角色组合的额外乘数；该布置的实际人数、站位和覆盖仍正常参与计算。
- 重写 V3 的可利用空间组合，减少多个正向修正叠加后大面积截断到 1 的现象，保留覆盖差异的梯度。

这些改动没有加入“某个阵型名称固定击败另一个”的胜负表。当前已验证的是方向、宽度和覆盖的对手相关效果；全阵型、全职责的平衡仍需更多真实阵容样本。

### 减少重复计算

已解析并冻结的参数直接复用；V3 的静态阶段投影按实际访问的进攻方与阶段计算；无需返回的旧静态完整投影不再重复建立。缓存限定于当前参数对象或当前链的快照，比分、体力、伤停与阵容更新后的新快照重新计算。

V2 的计算路径保留。测试验证惰性/原有阶段投影结果一致，以及同种子的比赛输出可复现。

## 完整比赛对照

Windows / Node.js 24.22.1。最终配对组共 288 场，包含 V2 与 V3；另跑 48 场相同 V3 规则但关闭分组抽样的对照。合成球队统一原始属性、默认分线，开局/领先/落后采用同一策略，晴天、标准裁判，交换双方位置。

同实力组每种配置有 48 场，即 24 个种子对。以下标准差按 N−1 计算。

| 配置 | 净胜球标准差 | 平均总进球 | 平局 |
| --- | ---: | ---: | ---: |
| V2.1 | 1.566 | 3.167 | 13/48 |
| V3.0 | 1.176 | 3.063 | 18/48 |
| V3 相同规则，独立抽样 | 2.004 | 3.021 | 12/48 |

本批 V3 相对 V2 的净胜球标准差比为 **0.751**；按配对种子聚类的 5,000 次 bootstrap，近似 95% 区间为 **[0.568, 0.976]**。相对相同 V3 规则的独立抽样组，比值为 **0.587 [0.406, 0.839]**。这支持分组抽样确实降低了波动，平均总进球没有出现明显上移。平局增加是这组样本中同时观察到的变化，需要继续监测。

“标准差下降约 25%”仅描述本批同实力样本，不能解释成所有比赛的随机性都下降 25%，也不是长期胜率的保证。

属性优势仍存在：V3 的全属性 88 对 80 组有 16 场，平均净 xG 约 **+0.465**。88 方全力进攻、80 方采用反击组合时，平均净 xG 约 **+0.270**。这两个小组各只有 8 个种子对，只能作为战术取舍的探索性结果，尚不足以断言某种战术必定抵消 8 点属性差。

原始结果：`outputs/engine-v3/paired.json`、`independent-equal.json`、`summary.json`。每个结果保存种子、双方顺序、比分、xG、射门与耗时。

## 对手相关的战术诊断

固定第 30 分钟、0:0 和满体力，组合攻击左/右与对手防守左/右四个条件，各 8,192 条链，共 **32,768 条**。比较“打空侧”与“打覆盖侧”，使用共同种子扣除单纯偏左/偏右的基准差异。

配对交互项 `LL + RR − LR − RL` 的原始射门质量代理值为 **0.0927 / 100 条链**，近似 95% 区间 **[0.0536, 0.1317]**。这里的左右方向经过双方视角转换；结果支持针对对手覆盖改变攻击方向产生正收益。

该值是固定状态、校准前的链内射门质量代理，不能当作正式比赛 xG、进球或胜率。诊断工具只对冻结快照缓存纯几何函数，16 条完整链输出已与原生实现逐项比对一致。原始数据和全部配置见 `outputs/engine-v3/tactical-probe.json`。

## 验证与边界

- 快速回归：61 个测试文件全部通过，日志 `outputs/tests/2026-11-03T09-57-24-000Z/report.json`；新增的 V3 比赛复盘识别检查另行通过。
- 真实 HTTP 服务验证默认 V3、建队、AI 训练和观赛的实际版本；联赛/杯赛/友谊赛默认 V3、显式 V2/V1 入口及 Worker 校验有定向检查。
- 单元检查覆盖：两个防守方、五个阶段的方向传递；宽度覆盖取舍；中场边界连续性；抽样频率与方差；不按比分/强弱补偿；序列恢复；投影复用与整场可复现。
- 275 个 JS/MJS/CJS 模块语法检查通过；`git diff --check` 通过。
- Chrome 1440×1000 和 390×844 注册/进入联赛通过，无 pageerror 或横向溢出，审阅输出在 `outputs/browser-review/`。
- V2.1 参数文件和显式 V2 路径保留。已有完整长跑集的历史失败/超时不能计入本轮全绿，见 `YFFM1-IMPLEMENTATION.md`。

本轮没有重做比赛时钟、180 条链、加时和点球流程。“拖延时间真实消耗剩余回合”的完整改造仍在后续路线中。真实球员属性组合、传奇/X 球员、替补深度、不同天气与长期联赛也需要继续扩大样本。

本轮实现与结果均在本地，未推送、部署或发布安装包。
