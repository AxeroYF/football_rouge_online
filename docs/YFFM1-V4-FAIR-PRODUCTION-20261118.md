# V4 同轮分组生产（本地验证）

同轮八场比赛在最多两个生产进程中交替推进，每个进程最多四场。每场仍独立锁定内核、输入和生产目录；在异步录像写入期间让同组其他比赛继续计算。默认每进程四场，旧调度文件缺少配置时保持每进程一场的解释。

工作进程退出或取消后，调度器等待所有子进程关闭再返回。各场错误单独记录；业务结算仍按队列顺序，前面的失败会阻止后面越序结算。进程中途终止后的部分录像文件只允许按确定性重演验证并补全。

公开清单只生成已发布的分块索引、时间、球队名和完成标记。私有完整清单仍用于磁盘历史校验，但 HTTP 刷新不再额外深复制它；默认调用 `refresh()` 仍返回独立快照。公开数据不能通过修改返回值改变内部发布状态。

## 已取得的证据

- 八场真实阵容完整比赛在不限资源演练中约 53.9 秒完成，比分和清单字节与先前逐场生产一致；清单包含全部三视角分块指纹。
- 第一次实际分组容量测试未通过：120 秒未全部完成，head P95 约 161 ms。保留失败证据。
- 减少私有清单复制和测试观察器的队列全量扫描后，iteration2 在约 118.0 秒完成八场，十个客户端 head/分块 P95 约 54/72 ms，首批画面约 0.9–2.0 秒出现。全 Windows Job 峰值私有提交内存 419192832 字节。
- 同预算 iteration3 重复通过：约 118.1 秒完成，head/分块 P95 约 56/82 ms，全 Job 峰值私有提交内存 423010304 字节。两次完成时间均接近120秒上限，仍需为综合业务负载预留资源。
- 当前源码重新通过八场完整真实阵容演练（约56.7秒，不限资源）、原 JSON/分片存储各八场消费与重开幂等验证，以及实际账户的桌面/手机回放验证。单元测试和源码归档由独立验收脚本生成。

## 证据边界

容量测试通过 Windows Job Object 对服务和子进程整体限制两个逻辑处理器、2 GiB 内存；客户端在限制之外。测试使用本地回环网络，未连接云主机，未模拟香港网络或云磁盘。测试消费者仅处理最小个人统计，未包含原资产、轮次奖励、预测生成和其他业务 HTTP 请求。不能把它视为生产综合容量结论。

此前44号验收的八场180秒证据属于逐场生产版本。本阶段独立保留容量和源码证据，不替换旧验收。
