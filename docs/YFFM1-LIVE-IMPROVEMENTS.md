# YFFM1 直播改进记录

日期：2026-11-12。落实直播策略评估中的第 2、3、4、5 项。

## 观看效果

- 进球、点球、红牌、伤退等事件在战况区顶部独立停留 6 秒；战术切换与比赛阶段事件停留 3.5 秒。停留后移除置顶条，原事件仍保留在列表中。
- 连续重点事件依次展示，战术消息合并为最新一条；入场不补播整场历史。置顶区只保留时间、类型和正文，字号及面积放大，直接复用列表的事件渲染器与配色。
- 比分、分钟、球场、数据及事件列表一直使用最新服务器状态。重点事件演出不暂停模拟，也不延迟结算。置顶事件有自己的分钟标记。
- 普通事件持续进入列表，采用轻微入场动画；阅读旧事件时保留滚动位置和展开状态。系统减弱动画偏好生效。

## 战术说明

转播增加当前预案、比赛心态、组织方式、防守区块、得球策略、对抗强度。切换事件记录当时比分、净胜球及触发条件，直播和终场详情共用同一事件数据。

“最近机会”可展开查看实际事件正文、细节及 xG。扑救事件按实际进攻方归属，不把守门员的所属球队当成创造机会的球队。这是比赛事实展示，不将战术原则直接解释为单次进球的确定原因。

完整镜像继续显示公开阵型及比赛表现；对手新增的原则、预案、触发条件、职责等字段以及战术事件细节在服务端过滤，终场报告也使用相同规则。

## 观赛恢复与刷新

在线人数按现有 30 秒心跳清理，清理后保留本场恢复资格。重新入场复用已知 token，避免重复增加人数。公开赛事在后台期间结束，也可在现有归档保留期内读取最终快照。

客户端遇到会话过期会调用专用恢复接口；私有训练携带账号身份并核验创建者。恢复只操作观众会话，不创建比赛、不调用收费流程。账号失效、无权观看和比赛已过期与临时网络波动分开处理。退出期间到达的响应被丢弃，恢复中新建的观众会话也会清理；同一观赛会话不会重叠轮询。

服务端对已经授权的公开快照计算 revision，覆盖统计、体力、评分、战术、场地、比赛阶段和终场报告等；仅倒计时变化不触发刷新。旧房间直播没有 revision 时，前端使用完整公开状态指纹。继续保留节点复用、背景节点与滚动位置。

## 本机测试

1. 重启 `npm run dev`，浏览器刷新；进入“阵容战术 → AI 对战 → 开始对战”，也可从电视台观看正式比赛。
2. 有进球或红牌时观察顶部放大的置顶消息；同时确认下方仍进入新事件，约 6 秒后置顶消失。连续重点事件应依次显示。
3. 检查双方当前战术和预案。进球改变领先或落后状态后，预案及切换时间、比分条件应与真实事件一致。展开最近机会可读到球员和事件信息。
4. 对公开直播切到后台超过 30 秒，让其他窗口刷新电视台触发清理，再返回。应恢复原直播；若已终场，显示最终状态。普通网络断连继续使用退避重试。
5. 完整镜像对战只应展示自己的详细战术；对手原则与预案应显示已保护。恢复观看后金币不再减少。
6. 手机检查 320/390px 宽度；大屏检查 1440px、2560px 宽度。重点消息可换行，事件列表保持可滚动。
