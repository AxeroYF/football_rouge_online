# V4.5–V4.6 机会质量与战术过程

已验收版本 `4.0.0-prototype.6`，联合完成 V4.5–V4.6。正式引擎、真实存档与预测 V1/24 样本保持原状。完整证据见 `outputs/v4-tactics-20261117/acceptance.json`。

79 项 V4 测试、16 项旧引擎回归、48 段组合、17 个专项场景及完整比赛／手机浏览器通过。96 次单因素对照六项行为指标通过。

训练 128 场、独立留出 256 场分别运行 600 秒和完整双半场。完整留出集场均进球 1.895、射门 22.871、传球 1109.17、成功率 74.86%、接球失误率 9.31%、犯规 29.07、黄牌 4.18、红牌 0.148；零进球 23.83%、六球以上 4.69%、球在比赛中时间占 74.78%。均通过既定工程门槛，零进球比例和有效比赛占比接近边界，后续真实阵容仍须复核，不能称作真实联赛拟合。

## 已实现的闭环

- 射门候选根据球门张角、距离、压力、球路封堵和门将覆盖评分，保存比较中的传球、带球和射门。评分不是 xG；进球仍由真实球路、触球和越线产生。
- 传球比较前进距离、接球空间、到达时间差、当前球路阻挡、弱侧和倒三角接应。推进记忆只提供小幅选择激励，不指定下一次传球或强制射门。
- 独立指令覆盖预设，比分预案继承默认指令，只在实际比分变化后切换。记录当前预案，断点恢复保持一致。没有主动临场换人或临场改指令接口。
- 留守、接应、套上、补位、压迫与回追由不同球员承担。压迫者被越过后必须实际回到球门侧。左右套上均须等边卫实际回位才解除补位。
- 边路深入后，中锋回到球后中路接应，远侧边锋进入后点，第二接应点保留纵深。仍为地面球，传中与争顶属于下一阶段。
- 事件解释可回溯原始出球决策和同一控球阶段的协同背景；不把背景强行描述为进球原因，不使用未来结果重写选择理由。

## 配置

`team.instructions` 可以部分覆盖 `width`、`press`、`directness`、`lineHeight`、`compactness`、`route`、`overlap`、`lossReaction`、`restDefense`、`clockManagement`。

`team.scorePlans.leading` / `.trailing` 使用相同字段；缺失字段继承默认配置。宽度范围 0.45–1.2，其余数值指令范围 0–1；非法字段和越界值拒绝生成。预案不是自动保证领先方守住或落后方追平。

实验室支持一项数值指令对照与预置的领先／落后方案。页面显示生成时锁定的配置，修改控件后须重新生成。

## 验证与过程证据

`outputs/v4-tactics-20261117/` 保存当前迭代、场景、浏览器和对照报告。`scripts/verify-v4-acceptance.mjs` 必须通过，才能生成正式阶段验收。

- `compare-v4-instructions.mjs`：固定合成阵容，单项指令变化，双边、多种子。检查宽度、防线、压迫时间、留守人数、传球推进距离和计划观察时间。相同种子不代表轨迹分叉后每次随机抽样仍成对。
- `diagnose-v4-tactics.mjs`：排除同预设交手，报告分预设胜平负、对手与主客拆分、Wilson 区间。用于发现严重偏差，不把预设整体差异当单项因果效应。
- `calibrate-v4.mjs`：完整两半场和独立片段，统计射门机会分组、进球尾部、传球、接球失误、犯规、牌、球在比赛中的时间。
- `explanation.js` 只读事件，没有模拟或随机数依赖。解释与原始证据一同锁定，播放器只显示游标之前内容。

第五阶段留出集已因高比分尾部失败而用于诊断，不能再次标为独立验证。最终联合验收必须采用新留出种子，并核对报告源码哈希。

## 已发现并修正的问题

第五阶段旧预设训练中高压 47/48 胜，左侧套上 0 胜。主要表现为安全回传循环、被越过的压迫者继续追球、宽侧进入前场后缺少球后中路接应。不能只降低全局进球率掩盖此问题。

过强推进激励会降低传球成功率并增加近身争抢；过强安全传球收益会使球员在门前也反复回传。所有失败报告保留，未通过的迭代不宣称验收。现阶段逐项调校选择收益，保持执行误差、物理触球、纪律判断独立。
