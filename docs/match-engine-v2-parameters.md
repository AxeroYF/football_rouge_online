# 比赛引擎 V2 参数与区域空间模型

> 2026-08-01 alpha4：V2 已接入本地测试服 YDL 联赛，完成整轮直播、整数分钟、裁判天气、中文多人播报、助攻详情和低 xG 校准。正式环境仍默认 V1；`versus/league-service.js` 已包含测试服版本路由。

## 当前已实现

- 各控球阶段重新投影阵型，无球前插按位置职责分层发生，并保留后场保护。
- 路线分为 `structured`、`direct`、`counter`；断球方可从真实断球区域发起下一条反击链。
- 每条链带分钟、实时 V2 比分、体能累积、天气和裁判状态；条件特性据此使用有限状态快照。
- 球队快照复用正式特性与前两条国家/俱乐部羁绊；S 使用统一传奇定义，X 使用成长后的 26 项、位置和已选特性。
- 对抗失败可产生犯规、牌、定位球和点球；恶劣天气事件独立记录，不重复修改射门概率。
- `match-engine-v2.js` 将 180 条控球链串成完整 90 分钟比赛，支持 `createV2Match`、增量 `advanceV2Match` 和一次性 `simulateV2Match`。
- 红牌、二黄变红会移除球员并记录停赛；伤病会使球员离场、记录伤停场次，人数不足 7 人时比赛终止。比赛中不允许换人。
- 定位球执行链包含任意球、角球、主罚者、传中/落点、争顶、解围、定位球射门、点球和门将扑救；普通射门包含射正、扑救、脱手、补射和进球。
- 动态战术按开局/平局、领先、落后实时切换，并同步位置预设、比赛状态和播报；`commentary` 与 `publicV2Match` 输出完整公开结果。
- YDL 正式特性池为 18 张，新增“顺风战士”“赖着不死”“大巴司机”；“极限一换一”仅保留为后台草稿，不进入正式池。
- 报告新增路线、纪律、天气事件、羁绊、S/X、特性来源和完整比赛执行统计。

## alpha2 小样本校准

- 200 场固定种子样本：V1 为 3.005 球/场、3.207 xG/场；V2 为 3.371 xG/场、3.375 链进球/场，进球/xG 为 1.001。
- 校准后机会形成基线为 `0.315`、射门终结基线为 `0.09`，点球约 0.26 次/场；这些数据只用于 alpha2 控球链基线，最终结论须使用 alpha3 完整比赛对照。
- `4-2-3-1` 的前腰/边锋已能动态进入高级区域，但阵型产出仍低于 `3-4-3`；下一优先级是职责化跑位与禁区占位，不使用阵型名称固定倍率。
- 该历史校准只针对 alpha2 控球链，不代表 alpha3 完整比赛执行器的最终平衡结果；需要重新运行完整 V1/V2 对照。

当前 V2 只建立独立参数和空间计算底层，不接入正式联赛，也不修改 `versus/match-engine.js`。V1 仍是唯一正式比赛引擎。

## 参数分层

1. 能力层：26 项游戏内能力以及 13 组归一化场景指标。
2. 战术层：心态预设、9 个连续战术维度和打法调整模板。
3. 空间层：5 条纵向通道 × 4 个推进阶段，共 20 个区域。
4. 状态层：体能、比分、人数、比赛阶段和控球链频率。
5. 环境与事件层：天气、裁判和独立随机事件。

## 统一球场坐标

双方的自由战术板都按“己方门将在下方”保存。空间模型把主队和客队转换到同一个世界坐标：

- 主队：`world = { x, 100 - y }`
- 客队：`world = { 100 - x, y }`

因此双方球员可以在同一区域直接争夺空间。输出客队结果时再旋转 180 度，让两队都以自己的进攻方向读取 `defensiveThird → buildUp → finalThird → box`。

## 阵型与战术互动

每名球员不会只落入单一格子，而是按距离衰减向附近区域投影。贡献同时取决于：

- 战术板实际坐标和模型推断的场上位置；
- 26 项能力聚合出的控制、进攻、防守、压迫、抗压和支援；
- 体能以及主位置、副位置、同位置组或客串的适配度；
- 心态、防线高度、压迫、进攻宽度和紧凑度造成的有限站位位移。

双方在每个区域共同计算控制率、局部人数差、人数过载、压迫差、可利用空间和推进优势。区域连接还会比较本方相邻区域的支援与对手在传球路径上的压迫。

这使战术收益和代价由阵型互动自然产生：边锋拉宽能争夺边路，高位压迫能把压力推向前场但会留下身后空间，低位防守能回收本方三区但会让出前场控制。

## 输出结构

`buildV2SpatialMatchup([homeTeam, awayTeam])` 为每队输出：

- 20 个本方视角区域及双方贡献明细；
- 区域控制、过载、推进优势与可利用空间；
- 区域间连接质量；
- 中路、边路、最后三区、禁区存在感和强连接摘要；
- 最值得利用的 5 个区域。

空间结果目前只供 V2 后续控球链使用，不参与 V1 比赛结算。

## 六阶段控球链

`simulateV2PossessionChain([homeTeam, awayTeam], options)` 执行：

`possession → buildUp → progression → finalThird → chance → shot`

- `possession`：比较双方组织区控制、支援及战术节奏，决定本次控球方。
- `buildUp`：从本方防守三区沿区域连接进入组织区，对抗对方前场压力。
- `progression`：依靠推进能力、抗压和连接质量进入最后三区。
- `finalThird`：比较局部控制、人数过载与空间，把进攻送入禁区区域。
- `chance`：由当前禁区区域的机会创造者与真实覆盖该区的防守者对抗。
- `shot`：只在前五阶段成功后计算最终进球概率；该概率同时记为本次机会的 `xG`。

每一阶段均输出唯一负责人、当前本方与世界区域、参与球员、成功概率、空间因子、区域连接和终止原因。开启 `recordRandomRolls` 后还会记录随机判定值，便于平衡诊断复现。

断球者只能来自对方在事件区域的实际贡献者。区域无人覆盖时，失败会记为非受迫失误，不会虚构远距离抢断者。前锋只有在高位站位确实覆盖组织区时，才可能完成前场断球。

## 叠加原则

- 属性构建顺序：基础能力 → 强化 → 特性 → 默契 → 羁绊。
- 执行修正：位置 → 状态 → 环境。
- 球队修正：战术 → 空间。
- 同一来源不能跨域重复，同一比赛结果只能由一个阶段负责。
- V2 的最终 `xG` 将等于射门阶段的最终进球概率，不再叠加第二套终结公式。

## V1 与 V2 全量对照模拟

配置文件：`versus/v2/engine-comparison-v2-config.json`

运行：

```powershell
cd D:\Project\game_test\.worktrees\s4
npm run compare:engine:v1-v2
```

默认模拟 30,000 场配对样本。每个样本使用相同的确定性球员阵容、战术板坐标、开场心态、打法、天气和裁判：V1 与 V2 都运行完整 90 分钟比赛，V2 每场执行 180 条控球链并结算完整比赛事件。全量共包含 540 万条 V2 控球链，固定最多使用 10 个 worker，并逐场显示完成数量、百分比、已用时间和预计剩余时间。

输出：

- `outputs/S4比赛引擎V1-V2全量对照-alpha4-10core-progress.json`：全量聚合结果。
- `outputs/S4比赛引擎V1-V2全量对照-alpha4-10core-progress-raw-samples.json`：500 场诊断样本。

聚合结果按阵型、心态、打法、生态阵容及双方对位分别对比 V1 和 V2，并记录 V2 阶段成功率、平均概率、空间因子、区域路径、终止原因、断球角色、红牌、伤病、定位球、战术切换和播报事件。射门结果额外按 xG 区间统计射门数、进球数、转化率和进球/xG；诊断样本保留进球射手、助攻、门将、进攻方式及完整中文播报。

当前 V2 对照报告唯一明确未消费的比赛机制是换人计划；YDL 比赛中不可换人，因此该项保持关闭。传奇特殊能力按 YDL 规则关闭，不属于待接入项；正式联赛接入也仍需用户验收后进行。
