## 一、 核心架构与业务红线（Codex 修改代码时严禁触碰）

1. **只改表现层与视图结构，不改游戏规则与后端业务公式**：
   - 十一人制足球；联赛分 **A、B 两级**（每级 8 队，双循环共 14 轮）；杯赛 16 队（两回合淘汰，决赛单场）。
   - **已停用/屏蔽功能严禁重现**：严禁在导航、主页或弹窗中出现“赛季总决赛”入口或“X 球员”相关入口。
2. **阵容与换人规则约束**：
   - 阵容战术页必须保留 **【默认 / 领先 / 落后】三套预案** 以及 **【不同赛事绑定阵容方案】**（如联赛主力方案、杯赛轮换方案）。
   - 赛前轮换与被动换人已有后端规则，**严禁在比赛直播页或战术页擅自新增“盘中主动换人”或“盘中即时战术按钮”**。
3. **比赛直播与比赛记录近期决策保留**：
   - **比赛直播常态界面**：默认展示 **双方阵容/球员卡、实时比分、文字事件流、比赛技术统计**。**严禁把全程小圆点 2D 播放器设为主界面默认视图**；仅在关键事件（如进球、红牌、点球）旁提供“小圆点回放”按钮，点击后在局部浮层或抽屉中播放对应 15 秒时段的真实小圆点动画。
   - **比赛记录精简**：仅保留比分、重点事件、比赛统计和球员表现评分，**严禁重新加入大段 AI 教练诊断、战术长篇复盘和调整建议**。
4. **数据展示三大铁律**：
   - 统一使用 **“控球率”**（双向百分比进度条），**严禁引入旧版“控球链”模块**。
   - **xG（期望进球）** 属于估算值，界面上凡出现 `xG` 必须在标签旁固定渲染 `[估算]` 徽章（如 `期望进球 xG [估算]`）。
   - **缺失数据展示**：当历史比赛或某项统计缺失时，必须渲染明确的缺失状态 `— (未记录/未采集)`，**严禁用虚构的 `0` 或 `0.0` 代替**。
5. **现有视觉资产与手动裁切参数保护**：
   - 现有球员卡画包含用户手动调整过的裁切和偏移定位参数（如 `scale`、`offsetX`、`offsetY` 或 CSS `transform/object-position`）。重构球员卡容器时，**必须在外层做固定比例裁剪框（3:4），内层原样透传数据库中的定位参数**，严禁重置或覆盖已有卡画坐标。
6. **性能与可用性硬性要求**：
   - 数据刷新/轮询更新 DOM 时，**必须保持当前滚动条位置（Scroll Position）、折叠面板展开状态和当前选中的页签/球员**，严禁整页闪烁重置，且不增加后台高频轮询。
   - 所有核心操作按钮（检查阵容、进入直播、替换球员、处理待办）必须**常驻可见**，严禁依赖鼠标悬停（Hover）才能发现。
   - 状态区分不能只靠颜色，必须同时具备 **颜色 + 文本标签/图标**（如 `[胜]`、`[停赛]`、`[我方]`）。
   - 禁止全屏背景视频、持续粒子特效、重度高斯模糊和无限循环动画作为默认配置；全局支持 `prefers-reduced-motion` 及手动“减少动效”开关。

### 2. 字体与数字排版规则
- **中文字体栈**：`'Inter', 'PingFang SC', 'HarmonyOS Sans SC', 'Noto Sans SC', 'Microsoft YaHei', sans-serif`
- **比分与大标题展示字体**：`'Barlow Condensed', 'DIN Alternate', sans-serif`（字号 `36px–48px`，字重 `800`）
- **数据与表格等宽数字（强制）**：所有积分、净胜球、排名、倒计时、控球率、估算 xG、金币价格、球员属性列，必须添加 `.yffm-num`（`font-family: 'JetBrains Mono', monospace; font-variant-numeric: tabular-nums;`），确保上下行数字严格对齐。
- **字号阶梯**：
  - 主比分：`40px` / 行高 `1.0`
  - 页面一级标题（俱乐部名）：`20px–22px` / 行高 `1.3` / `700`
  - 模块卡片标题（H2）：`15px–16px` / 行高 `1.4` / `600`
  - 正文与列表项：`14px` / 行高 `1.5` / `400–500`
  - 表格数据与次要信息：`13px` / 行高 `1.4`
  - 角标与状态胶囊：`12px`（全局最小字号下限，严禁小于 11px）

### 3. 布局、间距与响应式规则
- **桌面端栅格**：最大宽度 `1440px` 居中，12 列 Grid，间距 `16px–20px`，页面内边距 `24px`。
- **桌面导航防挤压**：左侧导航栏固定宽度 `224px`（折叠态 `64px`）。二级导航统一放在右侧主工作区顶部的水平胶囊页签中，**严禁在左侧展开多层树形子菜单推挤右侧主画布**。
- **手机端（`< 768px`）独立重排（非等比缩小）**：
  - 隐藏左侧导航，改为 **顶部 48px 俱乐部身份资源条 + 底部 56px 五格固定导航（主场 / 赛事 / 阵容 / 直播 / 俱乐部）**。
  - **优先级重排**：第一层当前比赛卡 → **第二层待办事项（置顶到积分榜上方）** → **3行极简相邻积分榜（仅留名次/队名/已赛/净胜/积分）** → 第三层上轮战报与近期赛程（默认收起在 `<details>` 折叠抽屉中）。

## 三、 联赛主页（俱乐部主场）三层结构规范

### 第一层：俱乐部身份栏 + 当前比赛焦点卡（主视觉高度严格 ≤ 236px）
1. **顶部身份与资源条**：展示本队队徽（44×44px）、俱乐部名称、所属级别胶囊（如 `[A级联赛]`）、当前赛季与轮次（`S12 · 第 9/14 轮`），右侧展示适量的关键资源（俱乐部资金、全队平均体能、当前绑定战术预案）。
2. **当前比赛焦点卡（Scorebug 构图）**：背景使用克制的球场看台夜景底图加 `85%` 深色遮罩，展示主客队徽（48–64px）、主客场标签、赛事名称、开球时间/比分，并根据真实比赛状态自动切换主操作按钮：
   - **赛前（Pre-Match）**：显示开赛倒计时 + 主按钮 `检查阵容`（若有停赛/缺员直接标出人数）+ 次按钮 `查看赛程`。
   - **比赛中（Live）**：显示脉冲红标 `LIVE 67'` + 实时大比分 + 主按钮 `进入比赛直播`。
   - **赛后（Post-Match）**：显示 `全场结束 (FT)` + 最终比分与积分变化 + 主按钮 `查看比赛记录`。
   - **休赛期/无比赛（Off-Season）**：自然显示休赛期状态、上赛季最终成绩与新赛季抽签倒计时，主按钮切换为 `规划新赛季阵容`。

### 第二层：本队处境与真实待办（桌面 7:5 分栏）
1. **本队联赛处境与相邻积分榜（左 7 列）**：
   - 顶部 4 个紧凑指标卡：当前排名、当前积分/净胜球、与榜首及相邻名次分差、近 5 场战绩胶囊（`[胜][胜][平][负][胜]`）。
   - 下方仅渲染 **本队及上下相邻共 5 行积分榜快照**（手机端 3 行），本队行使用绿色左边框 + 浅绿底纹 + `[我方]` 标签高亮；右上角提供 `查看完整 A/B 级榜单 (16队) →` 弹窗或路由入口。
2. **俱乐部真实待办事项（右 5 列）**：
   - 仅拉取真实业务中的阻塞或提醒项：**红黄牌停赛/伤病缺员、主力体能低于阈值、首发不满 11 人、球员或赞助合同即将到期**。
   - 每条待办左侧带类型胶囊（`[停赛缺员]`、`[体能预警]`、`[合同待办]`），右侧带一键直达处理按钮。
   - **空状态铁律**：当球队全员健康、阵容齐整且无合同待办时，必须渲染清爽的 `✅ 全队健康且首发齐整，当前无待办事项` 空状态卡片，**严禁为了填满画面编造虚假提醒**。

### 第三层：近期结果与补充信息（桌面 4:4:4 三等分栏）
1. **上一场比赛摘要（左 4 列）**：主客比分、进球者、**控球率双向条**、**期望进球 xG [估算]**、全场最佳球员（MVP），右上角附 `比赛记录 →` 链接。
2. **近期三场赛程（中 4 列）**：清晰区分 `[A级联赛]` 与 `[16强杯赛]` 颜色胶囊、主客场标签与开球时间。
3. **核心球员状态与 3 行精简日报（右 4 列）**：顶部展示 1 名本队近期高光球员卡画条目，下方仅列 3 条高价值单行动态（如赞助奖金到账、球员强化突破、球场维护完成），**彻底消除与积分榜和战报的重复展示**。

### 【第四批 Prompt】俱乐部经营、交易市场、收件箱与数据刷新体验优化

请按照 DESIGN_SPEC.md 执行第四批收尾 UI 升级：
