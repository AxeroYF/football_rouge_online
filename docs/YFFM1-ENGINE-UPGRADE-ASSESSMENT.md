# YFFM1 比赛引擎升级评估：战术空间与随机性

评估日期：2026-11-12。依据当前本地 V3.0.0 / `v3.0-tactical-control.1` 代码、定向回归及隔离诊断。本文是建议方案，未修改比赛规则或线上数据。

## 判断

建议沿用 V3 的空间、球员职责、属性和进攻链基础，分阶段改造决策与时间模型。首选方向是：**阵容和指令决定可用行动，局势与球员判断决定行动选择，技术执行保留适度随机，比赛结果由机会累积产生。**

现阶段最有价值的工作是让战术改变真实行为及其代价，继续堆叠滑块、提高战术加成或提高分组抽样比例都不足以解决问题。也暂不建议直接重写成 22 人高频物理模拟；应先使轻量引擎的时间、球权和攻守转换连续，再评估更细的移动模型。

目标应分别衡量：比赛可复现、战术执行稳定、优势持续转化为更好的过程数据、最终比分的合理波动。固定种子解决复现，不会自行降低不同种子间的波动。

## 当前已具备的基础

- 四组战术原则、五档心态、有球/无球细节和球员职责都已经进入计算，并非只有界面。方向、宽度、连接、局部人数、阵型覆盖、身后空间、体力和天气均有影响。
- 球员职责已经影响移动、参与阶段、路线、留守优先级、消耗和越位。不能把这些已存在的功能当作新模块重复增加。
- 存在阶段动态阵型、抢断后的转换信息，以及开局/领先/落后方案切换；当前不是逐帧连续模拟。
- 阶段结果和进球已有按通道的混合分组抽样。配置为每组 12 个区间、阶段混合比例 0.65、进球 0.75；这些数值不是成功率。
- 黑哨、乌龙、群架的部分基础概率已经下调，继续削弱这类小概率事件的收益有限。

历史 [V3 实施记录](YFFM1-V3.md) 记载同实力合成样本的净胜球标准差从 V2 的 1.566 降至 V3 的 1.176，但其原始 `outputs/engine-v3/` 数据当前本地缺失。本次未重新验证这批历史统计，不能将其解释为当前所有阵容“随机性下降 25%”。

## 当前限制与证据

### 1. 多层加权抽取，使战术收益难以辨认

`possession-chain-v2.js` 的 `chooseRoute` 先抽取组织/直接/反击路线类型，再按连接质量、空间等加权选择目标；`chooseActor`、`chooseDefender` 继续加权抽取执行者，推进等阶段再判断成功，最终射门另行结算。参与球员选择已经考虑能力、职责和影响力，但没有统一的“当前持球人可采取什么行动、为何选它”的决策层。

这不等于所有抽样都应删除，也不能仅凭抽样次数断言方差增加多少。实际问题是：一项指令可能同时改变选择概率、空间、阶段加成和后续随机调用顺序，很难区分收益来自行动改善还是一次路径分叉。

### 2. 时间仍由固定链数反推

`ydl-league-engine-adapter.js` 固定常规时间 180 条链，120 秒直播；`runV2Chain` 按链序号计算足球分钟。`v2PossessionDurationProfile` 计算的是权重，`recalculateV2PossessionSeconds` 再将固定的已过时长分配给历史链。

因此拖延时间目前会影响进攻投入、阶段概率和控球时长分配，但不会真正消耗剩余比赛机会。不能描述为“这个设置完全无效”。本次同种子诊断中，拖延 0 与 100 都结束于 180 条链、90 分钟，射门和 xG 有变化，支持上述区别。

体力又主要按每条链扣除。未来改为可变链数时必须同步改为按时间和行动负荷计费，否则慢节奏、快节奏会意外获得不同的整场消耗待遇。

### 3. 连续攻守状态不足

当前丢球后会保存转换球队、区域和反击窗口；动态模型也已有阶段/转换投影及留守保护。缺少的是跨行动延续的实际队形、移动所需时间、压迫是否被绕过、反抢窗口剩余时间和二点球归属过程。

这限制了“丢球反抢还是回撤”“边后卫套边后谁补位”“调度转移后弱侧能否及时回收”等设置的深度。单纯增加阶段成功率修正，容易让这些设置继续共享相近的效果。

### 4. 比分状态直接修正部分概率

当前继承参数包含：领先控球修正、落后紧迫度、60 分钟后平局时的决断修正；此外非点球射门 xG 按领先球数每球乘数减 0.04，最低 0.82。

例如其他输入一致时，领先两球会将某次原本 0.20 的机会缩放至 0.184。这是比分条件下的规则，不是随机数，也不说明程序预设胜负，但会令实际战术以外的因素改变机会质量。

建议逐步把这类效果迁移到明确的行为：领先方选择减少前插、降低风险、控制时间后，机会数量及质量自然改变；落后方投入更多人后，同时暴露反击空间。迁移时须重新校准整体进球和强弱差，不能直接删参数就宣称升级完成。

### 5. 中断恢复并非原随机状态续跑

`LeagueService` 当前用 `seed:resume:chainIndex:eventCount` 重建普通随机函数；V3 的分组抽样计数有保存，但选路线、参与者、犯规等使用的普通随机状态没有保存。

本次隔离诊断固定合成阵容、晴天和标准裁判，在第 60 条链保存：

| 运行方式 | 最终比分 | 后续动作和事件 |
| --- | --- | --- |
| 连续运行 | 1:2 | 基准 |
| JSON 保存后按当前恢复种子续跑 | 2:2 | 从索引 60，即第 61 条链开始不同 |
| 同一 JSON 保存，恢复原随机状态的诊断对照 | 1:2 | 与连续运行完全相同 |

这是同一场比赛的结构性复现检查，不能据此估计真实联赛中受影响的比例。诊断通过重放已消耗的 844 次普通随机调用重建状态，仅用于隔离原因；正式方案应直接保存状态或采用可索引的随机流，不能靠每次恢复都重放历史调用。

证据：[probe.json](../outputs/engine-upgrade-assessment/probe.json)，可重跑：[probe.mjs](../outputs/engine-upgrade-assessment/probe.mjs)。

## 推荐的引擎结构

保留现有阶段作为战报及统计层，内部改为以下循环：

1. 读取足球时间、持球人/球区、实际队形、球员体力、攻守转换状态。
2. 将当前战术方案、职责和条件规则解析为行为约束与偏好。
3. 生成少量可行行动，例如回传、横向转移、向前传、带球推进、传中、射门。
4. 评估推进价值、成功概率、失球权风险、丢球后危险和负荷，再由球员判断力与压力决定选择。
5. 对选定行动进行技术执行判定，更新时间、球区、人员移动、体力和下一状态。
6. 输出实际行动、局势因素及结果，供直播和复盘使用。

建议每步先限定 3—5 个有效候选，避免全场全员搜索。候选评分可概括为“推进/得分价值 − 丢球风险 − 被反击代价 − 消耗代价”，权重由心态、职责和局势决定。它是待校准的设计，不是已经验证的足球价值公式。

明显更好的行动应稳定优先；近似行动允许有限变化。高判断球员应更容易识别可见机会，受压和低判断球员可能选择次优动作。不能让球员拥有对手未来行动的全知信息，也不能永远强制所有人选择同一个数学最优解。

技术执行继续保留与能力、压力、距离、角度、支援和体力有关的不确定性。防守者先根据距离、职责和到达时间形成对位，条件接近时再抽取，减少“谁被随机抽中负责防守”决定整次攻势的情况。

足球时间与直播时间分离：慢组织消耗更多足球秒数，快攻较少；直播仍可映射到约 120 秒，按时间预算分片推进。死球、补时、半场、加时和点球必须使用同一时钟边界规则。先采用可变时长的轻量行动，是否进一步细化移动步长由实测收益决定。

## 可以扩展的战术模块

| 模块 | 当前基础 | 建议升级后的操作 | 必须同时承担的代价 | 优先级 |
| --- | --- | --- | --- | --- |
| 攻守转换 | 得球策略、抢断区和反击窗口 | 独立设置丢球后短时反抢/立即回撤；得球后冲击/稳住 | 反抢消耗、被突破后的局部缺口；回撤可能放弃高位夺回 | 第一批 |
| 进攻留守与补位 | 职责、留守优先级，动态模型默认保护 3 人 | 设置更保守/均衡/冒险的留守原则，明确边后卫前插时的覆盖职责 | 留守越多，前场人数越少；投入越多，转换越危险 | 第一批 |
| 出球与接应 | 短传/长传、线路质量、支点回做 | 指定优先后场出球区域、组织接应点、受压时的备用路线 | 避开受压路线会减慢推进；强行找核心可被对手封锁 | 第一批 |
| 压迫策略 | 高中低防守区块、强度、方向和盯人 | 明确触发条件：回传、边线接球、特定区域；封线与上抢分工 | 强压迫需队友覆盖，失位与体力代价 | 第二批 |
| 机会选择 | 耐心/尽快起脚、远射和传中频率 | 用真实候选机会决定继续传递、倒三角、传中或起脚；增加目标区域偏好 | 更多等待可能丢失窗口；抢射增加低质量机会 | 第二批 |
| 定位球 | 选主罚者、争顶者及传球/争顶/射门判定 | 近点/远点/短角球、争顶与二点分工、留守人员和防守对位 | 抢点人数与反击保护竞争 | 第二批，可独立试点 |
| 条件战术与轮换 | 开局/领先/落后方案，已有换人和伤退处理 | 时间+比分+体力/黄牌/红牌条件，选择方案、换人或调整压迫 | 明确规则优先级、冷却和换人名额，避免方案反复跳变 | 第一批先做有限规则 |
| 针对性防守 | 整体方向与盯人 | 对区域/职责重点封锁，成熟后再增加指定对手对位 | 转移后弱侧空当、盯防被带离位置的风险 | 第三批 |

第一批的留守设置不能只新增“2/3/4 人”按钮：必须审计现有默认留守保护和“少于三名防守者”等结构惩罚，使冒险选项有实际收益及风险，避免新设置被旧保护规则悄悄抵消。

保留现有战术板拖动、阵容交换和替补席逻辑。新规则围绕既有坐标、职责、开局/领先/落后方案生效，不要求重做这些操作。继续使用球队整体方向雷达和队伍复盘，不恢复用户已移除的位置/战术适配度展示。

## 降低随机性的具体办法

1. **先保证复现。** 将普通随机状态和分组计数都纳入检查点，保存引擎版本、参数摘要、阵容快照、当前战术和指令序列；同一检查点在不同推进批次及重启后应得到同样结果。旧检查点缺状态时不能声称可还原原未来序列，应提供版本兼容处理。
2. **按领域拆随机流。** 决策、技术执行、射门、纪律、伤病分开；条件允许时采用稳定事件标识和可索引随机数，避免多生成一个表现事件就错位后续比赛随机序列。已有 V3 通道可以延续，但普通随机仍需补齐。计数器随机数可参考作者维护的 [Random123](https://random123.com/)；这是可复现基础设施，不是自动减少进球波动的办法。
3. **减少决策层的无必要抽签。** 战术先决定可行行动和人员任务，再比较候选收益；在价值接近、视野不足或受压时保留适量决策变化。
4. **保留且校准执行层波动。** 不把 xG 累到某个整数就强制进球，不按上一场输赢补偿，也不承诺优势方必胜。球员判断和执行能力分别作用，避免战术和属性互相替代。
5. **控制低可控重大事件。** 普通伤病、犯规与行动暴露、负荷、对抗关联；乌龙、群架等保留清晰条件并观察它们对结果的贡献。当前已下调，不再以统一砍概率作为主要升级内容。
6. **审计现有分组抽样。** 不直接将 0.65/0.75 拉到 1。它能降低部分连续极端结果，但会引入跨事件相关性；应检查不同射门次数、概率变化、定位球、比分分支下的频率校准和长串模式。已有固定概率单元验证不足以保证所有动态条件下都校准良好。

训练环境可提供“固定种子、冻结阵容、冻结天气、交换双方”的战术比较；它用于观察差异，不能把固定输入的训练结果解释成正式比赛的必然结果。该诊断工具可以保持开发/管理员用途，不恢复已屏蔽的批量模拟或服务器模拟入口。

## 分期建议

### V3.1：可靠性与可解释性

先完成普通随机状态的保存/恢复、领域随机流、参数与比赛配置锁定、动作级诊断、统计校准基线。登记比分修正、每条链消耗、留守保护等规则的效果归属，避免后续行为层和旧乘数重复计费。

同一阶段可以完善有限的条件战术：复用既有方案，以时间和比分条件为主，明确触发、优先级和冷却；任意新行为指令必须等引擎支持后再对玩家开放。

验收重点：连续运行、保存恢复、不同推进批次的输出一致；诊断能说明路线、人员和结果的输入因素，且不将“某因素有贡献”夸大成“它导致了这次进球”。

### V3.2：时间、决策与转换的核心升级

这是对两个目标收益最大的阶段：引入可变足球耗时、持球/球区和实际队形状态、有限候选行动评估、短时反抢/回撤、进攻留守及补位。将体力和伤病暴露改为时间与行动负荷，迁移比分直接修正到行为层。

验收重点：拖延真实减少剩余机会；快攻、耐心组织、反抢、回撤和留守都有可观察的过程收益与代价；不能出现反复回传无限拖延、反抢零成本、反击永不丢球等循环。

### V3.3：战术深度与反馈

在 V3.2 已稳定的状态和行动上扩展压迫触发、指定出球、定位球战术、针对性防守及更完整的条件换人。直播可解释“这次丢球源于何种空间和行动”，赛后报告展示执行情况、被限制的位置及代价。

若增加比赛中指令，建议仍以预设规则为主；实时指令使用服务器统一生效边界，避免网络延迟和频繁点击决定额外优势。当前约两分钟一场的节奏，也更适合赛前规则加少量临场调整。

版本号仅为建议的工作分组。规则应在新赛季/新比赛统一启用，运行中的比赛继续使用其锁定配置。AI、玩家镜像、正式比赛和存档兼容需要一并回归。

## 如何验证升级有效

- **复现检查**：多个保存时间点、分片大小、加时/点球、自动切换方案、换人/红牌和服务器恢复；同版本同输入要求动作、事件与结算一致。
- **战术交互矩阵**：同实力及不同实力，多个阵型和职责组合；比较短传对压迫、留守对反击、宽度对防守覆盖、传中对争顶等。分别统计控球推进、压迫夺回、危险失误、正常/转换 xG、射门质量、体力和犯规，再看比分。
- **有对照的随机实验**：相同场景用多种子、双方顺序交换及配对比较，报告差值和置信区间；冻结状态的局部实验与完整比赛结果分开。共同随机数可提高某些策略比较的效率，但收益依赖随机输入对齐和模型性质，不保证每种比较都降方差。参考 [Glasserman 与 Yao 的原论文](https://business.columbia.edu/sites/default/files-efs/pubfiles/4261/glasserman_yao_guidelines.pdf)。
- **概率校准**：按机会类型、概率段、能力/压力、阶段及比赛时间检查实际成功频率；分开检查“赛前机会 xG”和考虑射手/门将后的进球概率，不将二者混作一个指标。观察分组抽样产生的事件相关性。
- **降低随机性的验收**：先固定一套真实阵容基线，再看合理战术调整的过程收益能否跨种子稳定出现，同时观察净胜球标准差、强弱排序稳定性和极端事件占比。暂不承诺“波动再降 30%”之类没有新样本支持的数字。
- **性能与产品回归**：实测服务器并发、每次推进 p95、保存体积、直播延迟和镜像耗时；战术板/替补席原有交互、两分钟直播目标和新旧报告兼容均需保留。
