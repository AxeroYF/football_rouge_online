# YFFM1 V3.1：可靠性与诊断升级

日期：2026-11-12。当前默认比赛版本 `3.1.0`，配置标识 `v3.1-reliability.1`，模型 `match-engine-v3.1`。项目版本仍为 0.3.0，存储格式仍为 2。修改在本地完成，未部署或推送。

## 已完成

### 随机状态完整恢复

普通随机函数的内部状态和调用计数现在随比赛保存，V3 分组抽样的通道计数继续保存。运行时函数从这些数据重建，不再为新检查点用 `seed:resume:...` 开启另一条序列。

单文件联赛、分片联赛、独立异步直播检查点和内存复制均使用相同恢复逻辑。复制比赛后，随机调用绑定复制后的状态，避免闭包继续修改原对象而存档保存另一个对象。

新 V3.1 检查点缺失/损坏状态、分组计数或配置摘要时明确报错，不静默重抽。外部自行注入的 `options.rng` 仍可用于临时测试，但标记为 `external-unserializable`；反序列化后必须提供原外部随机函数，不能宣称可精确续赛。实际联赛/AI/镜像入口使用内置可保存随机源。

### 按领域拆分普通随机流

V3.1 使用独立的 `decision / execution / shot / discipline / injury / environment / presentation` 流，分别管理路线和人员选择、技术执行、射门后续与点球、犯规纪律、伤病、环境和表现。阶段结果及进球继续使用原有独立分组通道；已有按事件标识索引的随机项继续沿用。

增加诊断或表现随机调用不会挪动其他领域的序列。伤病或红牌真正改变球员/局势后，后续比赛仍然会随实际状态改变；领域隔离不表示可以删除一个真实比赛事件而保持后续所有动作相同。

### 锁定比赛配置

每场新 V3.1 比赛保存配置 ID、完整参数的 SHA-256 摘要、种子、初始阵容和战术、初始特性规则快照、环境、离线属性模式及强制诊断事件选项。联赛适配器同时锁定赛事类型、回合、常规/加时设置、原始总比分和开赛时间。

完整参数随 `match.parameters` 保存并在运行时冻结。摘要验证覆盖配置和参数；特性规则从开赛时的快照读取，后续管理员修改球员池或特性不会改变已经开赛的 V3.1 比赛。球员体力、比分、伤停及正在执行的方案继续作为可变化的比赛状态。

### 动作诊断与概率基线

- 默认记录各队各阶段的尝试、预测成功数、实际成功数、Brier 误差及概率分段；射门分别记录机会 xG、考虑射手/门将后的进球概率和实际进球。特殊必扑点球单列，避免污染普通概率统计。
- 记录实际预案切换的分钟、比分差、阈值及触发原因。它是执行记录，不是新的临场指令界面。
- 可选详细诊断最多保存前 16 条链：路线类型、路线目标、参与球员和防守人的候选权重、实际抽样值、阶段因素与概率。读取这些数据不额外调用比赛随机数。
- `ENGINE_RULE_OWNERSHIP` 登记比分修正、射门质量、体力、留守保护、结构惩罚和控球时长的作用层，为后续 V3.2 避免重复计费提供依据。
- 战报提供紧凑统计；种子、随机内部状态、完整配置和候选动作跟踪不会进入公开观赛快照。完整镜像的对手诊断和战术细节继续隐藏。

## 兼容与规则边界

新建正式比赛、AI 训练和玩家镜像默认使用 V3.1；已有 V3.0 比赛读取其原版本、参数、模型标识和抽样规则。V2 对照入口保留。

旧检查点没有保存原随机状态时，原未来序列无法还原。此类 V2/V3.0 比赛保留历史恢复方法，并记录 `legacy-fallback` 和迁移链序号；迁移后再保存，可从新保存点精确续跑。公开可靠性摘要可区分这种情况与 `exact`。

镜像 Worker 协议升级为 `v3.1-reliability-r1`，防止旧计算端被误认为与新引擎兼容；隐藏的批量/服务器模拟入口没有恢复。旧计算端需要更新程序版本。

本轮保留 180 条常规进攻链、直播时长、现有心态与战术原则、分组比例、比分修正、体力扣除和留守保护的原数值。战术板拖动、阵容交换与替补席操作未修改。可变时间、候选行动决策、反抢/回撤等属于后续 V3.2；评估中可选的时间条件预案编辑器也未在本轮新增。

配置锁定是对同一模型和运行环境的复现约束，不能代替未来模型代码的版本兼容。离线属性模式与存档锁定模式不一致时拒绝静默恢复，应使用原模式完成该场比赛。

## 本地测试方法

已有 npm 依赖时，重新启动 `npm run dev`。打开 `/api/versus/config` 应看到 `engineVersion: "3.1.0"`、`engineProfile: "v3.1-reliability.1"`；新开 AI 对战或镜像使用该版本。已有比赛保留开赛版本。

无需访问实际球队即可验证恢复和动作诊断：

```powershell
npm run test:engine:v31
npm run diagnose:engine:v31
```

诊断报告：`outputs/v31-diagnostic/report.json`。默认使用合成球队，在第 60 条链序列化，连续和恢复两种路径均跑至 180 条链；`exactResume` 应为 `true`。报告包含前 16 条链的候选与阶段因素。

更换诊断种子：

```powershell
npm run diagnose:engine:v31 -- --seed=my-seed
```

生成完整校准基线，或先跑较短版本：

```powershell
npm run calibrate:engine:v31
npm run calibrate:engine:v31 -- --quick
```

输出：`outputs/v31-calibration/matches.json`、`summary.json`。两种模式写入相同路径，短版本会覆盖上次结果，报告内有 `quick` 字段区分。均使用合成阵容和固定种子，不读取或写入玩家联赛存档，不增加前台批量模拟入口。

## 本次校准结果与限制

完整基线包含 V3.0/V3.1 共 64 场，晴天、标准裁判，冻结开局/领先/落后方案，包含同实力、全属性 88 对 80、耐心组织对高压；按种子配对、交换双方顺序。

| 场景 | V3.0 平均净 xG | V3.1 平均净 xG | 每版场次 |
| --- | ---: | ---: | ---: |
| 同实力 | -0.084 | +0.042 | 16 |
| 88 对 80 | +0.324 | +0.576 | 8 |
| 耐心组织对高压 | -0.103 | -0.378 | 8 |

同实力组净胜球标准差 V3.0 为 0.929、V3.1 为 1.025；另外两组样本更少。本轮并没有据此证明全局比分波动下降，也没有按这些小样本调整战术强度或胜率。基线用于发现异常和后续扩大真实阵容评估。

抽样器另外覆盖 4/12/24/60 次射门、4 档固定概率和一种随已进球情况变化的概率，共 20 个场景，每场景 4,096 个独立种子。固定概率组平均命中频率与输入概率接近；随比分变化组在 12/24 次射门时，实际频率减预测频率分别约为 **+0.465 / +0.254 个百分点**，近似区间未包含零。

这提示分组抽样在自适应概率下存在相关性/校准取舍，不能把固定概率测试推广成所有动态条件下完全校准。V3.1 保留原 0.65/0.75 混合比例，登记这一监测项；不能将比例拉满并声称必然更公平。区间按独立种子聚类并使用正态近似，多个场景同时比较时仍应结合后续样本判断。

完整测试汇总和本次检查日志见 `outputs/v31/validation.json`。升级前源码备份在 `outputs/backups/engine-before-v31-20261112/`。
