# YFFM1 战术模块扩展规划

日期：2026-11-10。基线：当前本地 V3.0.0 / `v3.0-tactical-control.1`。本文件是规划，未实施新的比赛规则，也未执行新增战术的胜率或平衡实验。

## 结论

优先把已有的战术能力变成可独立组合、可看懂、能验证的模块，再增加新的比赛决策。建议第一期做“四类打法拆分、定位球人员安排、职责联动、执行反馈”，第二期扩展“得失球权转换、防反保护、条件应变”，第三期才推进常规赛中换人和真实时间消耗。

当前采用分区空间、阶段投影与控球链模型，适合表达进攻路线、人数投入、覆盖、参与者和事件选择。第一轮不以逐帧球员寻路或完整自由跑位脚本作为实现前提。

## 当前能力核验

- V3 的入口/配置位于 `versus/v3/`，共享实现仍在 `versus/v2/`。不能仅根据文件名判断运行的是 V2。
- 玩家已有五档比赛心态、七种旧打法、八个主要滑条、八个攻防细节选项、十九种外场球员职责，以及默认/领先/落后三套比分预案。
- 分拆的 `possessionStyle`、`defensiveBlock`、`transitionStyle`、`duelIntensity` 已有枚举、参数解析和部分规则消费。不过前台 `originalV2StyleForPlan` 会将旧分拆数据折回单个打法，联赛保存也重建白名单字段；不能仅增加四个下拉框就认为保存和实战已支持完整组合。
- 控球丢失后会记录夺回区域与下一次进攻的转换上下文，反击倾向影响反击机会。尚缺少玩家可配置的失球权后反抢/延缓/回撤决策。
- 动态阵型已有边卫内收/前插、远端收缩、职责相关移动与防反保护；当前配置的进攻保护人数目标为三人。不是一张完全静态的战术板。
- 定位球已有传球、争顶、机会生成及射门处理。`v2SelectSetPieceTaker` 在非角球时优先取场上队长，之后才按能力选择；`v2SetPieceTargetPool` 在有前场接应者时优先使用前场球员池。
- 当前默认常规比赛为固定 180 条进攻链，比赛时间与链序推进关联。`timeWasting` 会参与进攻投入和相关计算，不能等同于真正减少剩余进攻回合。
- 联赛的 `fitnessThreshold` 用于赛前首发轮换。引擎已有伤病换人和门将红牌应急换人，但常规的赛中体力换人、时点安排与完整名额/窗口策略需要另做。

## 第一期建议做成什么

### 1. 四类打法各有一个职责

保留“比赛心态”和八个主要参数的微调能力，但把旧“预设打法”改为快捷组合。快捷组合只填写各模块，不再与模块各自重复叠加同一种收益。

组织方式、防守区块、得球选择、对抗强度可以分别调整。第一期不另外增加一套节奏/宽度/防线下拉菜单去复制现有滑条。显示“模板基准 → 玩家微调 → 最终生效值”，并说明上限截断和约束。

需要统一旧 `style`、已有 `inPossession/outOfPossession`、分拆字段、细节项和原始滑条的解析顺序。同一阵容不能因为从旧接口或新界面进入就得到不同的额外加成。旧打法身份中的风险/收益规则要有明确迁移目标，不能在重构中意外丢失。

### 2. 定位球先让玩家选对人

先开放角球、任意球、点球的主罚顺位和争顶/保护人员。主罚人无效时按名单顺位回退，最后自动选择；场下、红牌或伤退人员不能继续参与。

队长保留领导力作用，主罚顺位独立设置。允许玩家明确安排高制空中卫参与争顶，不再仅因有前锋在场而排除中后场人选。角球防守接应与反击出口需同时考虑。

第二步再做近点/远点/短角球等套路。这些选项只有接到具体的接应区域、争顶与二点球路径之后才开放，避免只是给同一个概率换名字。

### 3. 职责联动复用现有能力

例如“左侧套边”可由左后卫的套边职责与左边锋的内切职责组成；右侧可独立保守留守。联动预设更新球员职责与相应配置，不产生额外的“配合成功率+X%”全局奖励。

保留能力适配和主/副位置的限制，并说明影响的是前插、宽度、出球、抢点还是保护。暂不同时开放大量单人微指令去叠加同一职责的收益。

### 4. 执行反馈与新模块同时发布

当前已有战术事件、分析快照与部分区域统计，可以先展示：当前实际采用的预案、切换原因、最终生效指令、主要路线和失权区域。

后续新增转换执行次数、反抢窗口内夺回次数、被突破后的射门/xG、定位球主罚与目标参与、保护人数的执行摘要。记录样本量和条件，不把一场的胜负或触发前后差值直接当作某个战术的因果收益。

## 第二期的关键规则

### 失球权后的选择

先利用当前“上一次失权 → 下一次转换”的事件边界实现一次有上限的处理窗口，不伪装成连续逐秒逼抢。

就地反抢依据附近人数、距离、工作投入、体能及对手第一接应点处理；失败必须进入被反击风险/回撤分支。延缓优先阻断向前线路，回撤优先恢复中路保护。避免在一条链中无限反抢或多次重复结算体能。

现实战术参考中，反抢同时强调丢球前的保护结构、丢球后的即时压力，以及无法立即施压时保护中路/传球路线；适合将这些取舍转译为当前分区模型，而不是直接添加全队防守数值奖励。[FIFA 训练资料](https://www.fifatrainingcentre.com/en/practice/elite-sessions/transition-to-defending/preparing-and-executing-counter-pressing.php)

### 有边界的自动应变

先开放分钟、分差和人数状态，后续再评估更复杂的场面数据条件。建议示例：

- 第70分钟以后且领先至少一球：采用领先预案，减少前插。
- 第75分钟以后且落后一球：采用追分预案，提高推进速度。
- 中后卫被罚下：先恢复防线结构，再根据比分决定保留哪个反击出口。

明确人员应急优先于普通场面规则，普通规则之间采用固定优先级；预案选择须能回退，重复触发要有明确边界。红牌应变保存为重排规则，不把十人阵容当作赛前十一人合法首发保存。

当前 `applyTacticalPlan` 存在按方案名、心态和打法判断是否重新应用的早退逻辑。扩展时必须加入方案/规则修订标识，避免同一个方案名称下改了指令却未重新应用。

## 界面组织建议

战术页维持球场为主视野，右侧使用“球队战术、球员职责、定位球、自动应变、执行反馈”几个清楚的模块。球队战术内再分有球、无球、转换。当前默认/领先/落后预案一次编辑一套，避免三套完整长表同时铺开。

界面显示偏好仍放到“游戏设置”；影响出场阵容、比赛概率和调度的战术必须跟随球队及阵容方案保存在服务端，可分享、可复现。

## 保存、兼容与验收

每个模块都必须贯通：默认值/旧存档迁移 → 服务端白名单 → 方案保存与版本冲突保护 → 阵容码分享及球员ID映射 → 比赛队伍/快照 → 实战消费 → 预览/战报 → 中断恢复。AI训练、镜像及 Worker 使用同一套解析和版本。

改变比赛概率或调度语义时发布新的引擎配置档，保留旧版本和历史战报。对预览与实战使用相同解析结果，缓存随阵容、体力、比分、人数和设置修订失效。

验收不以单场胜负为准：

1. 无新增字段时验证旧配置的兼容行为；同种子完整比赛与保存/恢复可复现。
2. 固定球员、交换双方、配对种子，分别对高位/中位/低位、不同宽度和不同实力对手评估。
3. 观察阶段通过率、路线占比、失权、反击/被反击射门与xG、体能、犯规及红黄牌；收益出现时，相应代价也必须实际发生。
4. 对定位球和转换使用条件场景补足样本，并以完整比赛和真实传奇/X阵容复核。自动应变还检查阈值边界、冲突、回退及每次触发日志。
5. 加入合理预算内的整场耗时和存档增量测量，优先累计摘要，避免为所有180条链重复保存大份完整空间数据。
