| 设置 | 选项 | 引擎中的作用 |
| --- | --- | --- |
| 丢球应对 | 就近施压 / 短时反抢 / 立即回撤 | 反抢窗口内根据附近人员和持球者抗压评估一次付费反抢；回撤优先恢复防守队形 |

## 引擎变化

### 比赛时钟

常规时间按两个 2700 秒半场推进，不再固定 180 条进攻链；每个动作消耗模拟足球时间。半场边界不会执行来不及完成的动作，定位球、补射也要支付时间。进球、伤停与换人有停球时间和有上限的补时；直播显示 `45+1`、`90+1` 等时钟。

常规直播仍映射到约 120 秒现实时间，加时约 40 秒，点球沿用原逐次展示方式。服务器每次只计算有限链数，延迟补算和一次算完使用同一规则。1800 条是安全上限，不是比赛目标条数。

### 连续状态与行动

球权、持球者、球区、阶段、转换窗口和球员实际位置跨行动链保存。实际位置按速度、体力和经过时间向目标位置移动；换球权后先从已有位置组织，半场才重新落位。它是基于区域的轻量状态模型，不是完整物理运动模拟。

每步从可行传球、直接推进、带球、转移、回传、创造机会或远射中保留最多五类候选。根据连接质量、区域控制、空间、方向、风险和球员判断比较，只在价值接近的候选中保留变化；明显更差的候选不再参与无差别抽签。带球耗时受到移动距离约束。每链最多八个主动作，回传/转移不会绕开时间消耗。

短时反抢窗口为 6 秒，一次尝试消耗 3 秒，必须有附近球员参与；成功率有上限。失败后对手继续处理，反抢者承担额外体力负荷。动作跨越窗口时，反抢跑动只作用于剩余窗口，随后回到正常目标队形。

留守保护作用于实际空间投影；V3.2 将结构模型最低后卫数改为 2，并停用原先额外的“少于三人”阶段惩罚，避免“增加前插”被旧保底与旧惩罚重复抵消。站位暴露本身仍影响防守。

### 时间负荷与比分规则

体力按活动时间、停球时间的折算负荷及参与反抢的冲刺负荷扣除。一次链末伤退或换人，不再让刚上场的替补承担整条链的活动负荷。普通伤病和天气伤病的每链概率换算成时间暴露概率；高位压迫原有强度因素保留。

取消通用的领先射门质量扣减，以及落后紧迫、领先控制、平局决胜等直接阶段概率补偿；比分通过已经配置的领先/落后预案改变打法。队长与球员特性中有明确条件的效果继续保留。V3.1 分组抽样系数不再额外上调。

### 兼容与诊断

新联赛、AI 训练、玩家镜像共用 V3.2。已开赛的 V3.0 / V3.1 比赛读取原版本和锁定参数；V3.1 专项测试显式固定旧参数，避免“旧版回归”实际上运行新版。

V3.2 保存连续状态及原有完整随机状态，恢复时校验时钟与坐标；参数和初始配置继续锁定。镜像计算协议为 `v3.2-continuous-tactics-r1`，计算端须使用相同版本。公开快照不提供完整流状态、种子或初始阵容快照；完整镜像继续隐藏对手战术细节。

保留阶段、射门概率和有限候选决策诊断，增加反抢尝试/夺回次数、活动时间及停球时间。六方向雷达仍是静态阵容/战术投影，不能表达完整比赛中每次反抢和时间管理的结果，不能当成胜率。

## 本机体验

```powershell
cd D:\YFFM1
npm run build
npm start
```

重启已有本机服务，打开终端显示的地址并刷新页面。修改三个新设置后观察“已实时保存”，刷新确认，再通过 AI 对战或玩家镜像开始**新比赛**。已有正在进行的比赛继续用开赛时的版本。

```powershell
npm run test:engine:v32
npm run diagnose:engine:v32
npm run calibrate:engine:v32 -- --quick
```

完整 80 场校准去掉 `--quick`。这些开发命令不恢复前台批量模拟入口。更完整的压迫触发、指定出球、定位球战术和临场条件指令属于后续 V3.3。
