# V4 完整赛季、赛季边界与录像保留

本阶段把原有 14 轮、112 场联赛和 29 场冠军杯交错推进，随后调用原排名奖励、金球奖、荣誉、归档、升降级和新赛程逻辑。赛季总决赛仍按现行产品规则停用。所有运行限制在标记的本地副本，真实存档和正式定时器不接入。

验收结果以 `outputs/v4-season-retention-20261118/acceptance.json` 为准；该文件生成前，本说明仅描述候选实现和验证要求。冻结源码保存到 `outputs/v4-season-retention-accepted-20261118/`，不得覆盖旧阶段归档。

## 完整赛季

`verify-v4-full-season-local.mjs` 先隔离五类数据路径，再启动原分片存储的真实调度。每场采用已冻结的 prototype.8 完整比赛内核；64 倍只用于公开时钟。联赛每 20 分钟一轮，前七轮之间推进杯赛。第二份全新 JSON 存储按相同任务、输入、结果和业务时刻消费 141 场归档，与分片结果对照。

验证覆盖积分和进球守恒、杯赛晋级、个人统计、伤停延续、钱包、卡包、收件箱、赛季奖励、荣誉、完整历史归档、升降级及新赛程。原系统新生成的流水和赞助邀请采用墙钟 ID；只有逐条业务内容完全相同、且均不属于原存档 ID 时，跨存储对照才建立对应关系。重开单个存储必须保持实际 ID 完全一致。

奖励和重置各有独立幂等回执，与业务状态一次提交。旧赛季重复请求优先返回原回执，不再重置新赛季。分片存储写入完整冷归档后，桥接层重新采用原摘要表示，避免误判内存和磁盘冲突。保存前后抛错及实际杀进程均须验证奖励、荣誉和升降级只执行一次。

赛季第 4 轮发现原战报归因的浮点边界问题：内核近身抢断用 `步起点 + 0.2` 判定三秒反抢窗口，事件时间却已舍入。战报现在按事件步号还原同一判定，接触球仍采用原接触时间。原内核、轨迹、比分和 RNG 均未修改，原统计一致性断言保留。
第 9 轮发现门将碰球失误后的二点头球仍带原传球决策编号。战报现在同时核对事件的来球者，只有仍属于原传球飞行段的头球才计成功传球或拦截；自由球头球不重复归功于最初传球。

## 录像生命周期

保留计划默认按压缩帧负载设置 16 GiB、最长 7 天、最短 2 天和最近 16 场；这些是可配置的本地默认值，尚未成为生产策略。容量不包括输入、结果、清单、冷归档和其他项目数据，因此不是总磁盘配额保证。
本次 141 场完整比赛的清单记录压缩帧负载为 1,761,617,482 字节，约 1.64 GiB。只读计划工具 `plan-v4-local-replay-retention.mjs` 在当前时钟保护全部 141 场；将规划时钟设为 2026-11-28 时列出 125 场候选、保留最近 16 场。两次都没有删除文件，这只是该样本和配置的计划结果。

未结算、未完整公开、正在生产、固定保留以及正在观看的录像不可清理。HTTP 鉴权和限流后取得读取租约；请求结束后保留 90 秒宽限，防止短暂断线触发清理。清理与读取共用同一个生命周期对象，整个本地根由单一宿主持锁。调用方必须让该根的所有观看入口使用该对象；多节点租约尚未实现。

执行器重新检查赛程、原结算回执、生产者锁、公开时刻、清单身份及完整影子结果。先原子提交过期标记，再逐个校验并删除清单中的压缩帧文件；拒绝越界路径和链接，不递归删除，不处理未列入清单的文件。输入、完整赛果、清单和结算回执继续保留，已清理比赛的结算重试仍可核验。

中断或删除失败时保留标记和剩余分块。重开后继续清理，损坏分块先保留现场。死进程锁需显式验证原 PID 已结束后恢复，活进程锁不能抢占。过期录像经原权限检查后返回 HTTP 410；播放器停止请求并清除比赛画面、球员任务、事件和时间轴。真实浏览器验证使用另行复制的完整决赛录像，不清理历史验收证据。

## 边界

本阶段不是资源限制或香港云容量验收。阶段 50 的 2 核/2 GiB/10 人混合负载结果只适用于其冻结源码。正式调度切换、自动清理、云连接及生产部署均未启用。后续需整合默认关闭的宿主编排、受控切换和回退，再对最终组合进行本地容量验证。原 V1/24 样本预测、既有引擎和真实存档保持保护。
保留输入和回执不代表可无限运行：当前热结算索引上限为 4096 场、赛季边界回执为 512 条，达到上限会拒绝新增而不会丢弃证据。跨赛季元数据归档和更长周期容量仍是后续工作；本次不删除这些结算证据。
