# YFFM1 前端性能优化记录

本轮只减少无意义的渲染、计算和请求，保持现有显示内容、布局、卡片数量、排序、交互和游戏规则。对照基线是本轮修改前的本地 YFFM1，已包含此前完成的更名和基础整理；本轮没有改动 CSS。

## 排查结果与修改

| 热点 | 原行为 | 当前行为 |
| --- | --- | --- |
| 联赛内容区 | 同页刷新也用 `innerHTML` 换掉内容树 | 同页按原模板更新差异，未变化的元素保持连接；切换页面仍按原方式初始化 |
| 强化选卡 | 把全部卡片搬进新模板，再替换整个强化区 | 保留强化区、仓库及未变化卡片，只增删选中的卡片和更新属性/文字，沿用原来的滚动位置恢复 |
| 阵容拖动松手 | 重写每个磁贴内部，替换默契线、分区、摘要等区域 | 保留磁贴及辅助节点，只更新差异；内容完全相同的阵容刷新跳过重建和重复绑定 |
| 直播 | 先生成旧三栏布局，随即删掉并生成 V2 布局 | 直接生成原来最终显示的 V2 布局，增量更新比分、球员状态、赛况和数据，保留原赛况滚动规则 |
| 列表、导航、顶部资源栏及独立电视台 | 内容未变也重建列表、徽标或面板 | 更新变化的节点，结果相同时不写 DOM |
| 后台刷新 | 并发读取同一直播列表；隐藏页面继续直播轮询 | 同时触发的列表读取共用一个请求；隐藏页面暂停相关轮询，返回前台后恢复；过期页面/账号的响应不会重新渲染页面 |

新增 `versus/public/dom-patch.js` 只负责把原模板同步到 DOM。卡片、球员及赛况使用稳定标识复用节点；表单同步 value、checked、selected，避免仅比较 HTML 属性而遗漏控件状态。阵容发生真实变化时仍保留原来的完整渲染与绑定流程；巨星之路的完整刷新路径也保留，避免影响它额外插入的重置面板。

## 本地对照结果

Windows、Node.js 24.22.1、系统 Chrome headless。通过临时账号正常建队并向隔离存档发放测试卡，共 **523 张卡片**。修改前后使用同一个存档和直播数据快照；比赛快照来自实际引擎，测试中固定了赛况历史以避免网络时间差。

以下为最后一次桌面尺寸 1440×1000 的样本，时间是同步脚本执行时间，不含网络往返及最终绘制。

| 场景 | 修改前 | 修改后 | 原有元素保留数量 |
| --- | ---: | ---: | --- |
| 选择强化主卡 | 50.0 ms | 9.2 ms | 6,034 → 6,625 / 6,639 |
| 选择强化副卡 | 51.8 ms | 8.6 ms | 6,034 → 6,623 / 6,637 |
| 强化页重复刷新 | 10.1 ms | 8.9 ms | 0 → 6,635 / 6,635 |
| 背包重复刷新 | 9.2 ms | 7.5 ms | 0 → 6,090 / 6,090 |
| 阵容重复刷新 | 4.0 ms | 3.8 ms | 0 → 763 / 763 |
| 阵容松手后的局部同步 | 4.2 ms | 3.5 ms | 614 → 763 / 763 |
| 直播进入下一分钟并新增进球 | 8.8 ms | 4.9 ms | 0 → 932 / 932，仅新增一条赛况 |

独立电视台相同数据刷新时，原先只保留 197 个元素中的 11 个，现在保留全部 197 个元素；这一样本脚本时间从 3.6 ms 到 4.5 ms，收益主要是避免重新布局和绘制，而不是减少每个场景的 JavaScript 时间。背包切换排序仍需移动大量卡片，不能把排序的真实工作算作冗余。

390×844 的浏览器尺寸也进行了同样对照。强化主卡/副卡脚本时间分别从 54.2/46.5 ms 到 15.2/14.2 ms；这只是手机尺寸的桌面 Chrome 测试，不是手机硬件实测。单次耗时受图片解码、布局、GC 和系统调度影响，不能据此推断全游戏 FPS、服务容量或所有设备的改善比例。

## 显示和行为验证

- 两种尺寸各 **24 个场景**：阵容、强化、背包、各联赛页面、电视台列表、独立电视台及直播。修改前后的 DOM 结构、文字、样式属性和表单值一致；只忽略用于复用节点的 `data-render-key` 属性。选卡检查了滚动位置与实际副卡选中结果。
- 直播截图进行像素比较，最后一次两种尺寸的最大通道差均为 0。检查允许 Chrome 合成文字/阴影时出现 1/255 色阶误差。直播的赛况滚动位置也与基线一致。
- 两种尺寸各执行 200 次随机节点插入、删除、排序、属性/文字及表单变化，结果与直接生成新 DOM 一致；相同模板再次更新没有 DOM 变更。SVG、脏表单值、稳定节点身份均有覆盖。
- 两个并发列表刷新只产生一个请求；隐藏页面不产生该列表请求；单元测试覆盖退出观赛或切到后台后忽略在途直播响应。
- 快速回归 **59 个文件、499 项检查通过**。完整长跑集已有的失败/超时仍见 `YFFM1-IMPLEMENTATION.md`，未将它们计为通过。

各联赛页面采用该测试存档的实际状态，其中尚未加载的球员目录、未开始的赛事包含对应空态；上述场景不代表全部业务状态的穷尽覆盖。最终源码语法检查 260/260 通过，观赛退出、俱乐部直播及 S4 界面的定向回归在 `outputs/tests/2026-11-03T08-02-31-833Z/report.json` 中通过。

原始性能报告与截图在 `outputs/performance/`，本轮快速回归报告在 `outputs/tests/2026-11-03T07-52-19-175Z/report.json`；这些输出不进入版本库。本轮不涉及线上存档、部署或发布。

## 复现

```powershell
# 未来修改前先保存 app.js 到一个临时文件，作为对照输入。
$env:RENDER_BASELINE_PATH = '.assessment/performance-baseline-app.js'
$env:BROWSER_CHANNEL = 'chrome'
node scripts/compare-rendering.mjs
```

需要本机 Playwright；如使用外部已有安装，可将 `PLAYWRIGHT_REQUIRE_FROM` 指向其依赖目录。该工具自行创建/清理临时服务和存档，关闭样本中的定时刷新，用真实渲染函数完成对照，不向发布代码添加测试全局变量。没有安装浏览器依赖的 CI 仍运行语法和快速单元回归。

首次进入页面仍按原逻辑生成全部可见内容。进一步改善大型存档首次渲染、赛事计算和真实设备上的帧时间，需要各自的实际性能记录；本轮没有引入分页、虚拟列表或改变动画规则。
