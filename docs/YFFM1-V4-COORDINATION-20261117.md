## 运行与观察

在项目根目录运行 `npm run dev:v4`，打开 http://127.0.0.1:4314。已打开页面需刷新。服务器只提供 V4 静态文件，浏览器 Worker 使用合成阵容生成片段，不导入正式联赛服务。

“观察场景”提供完整片段、接应与封线、套上后丢球、高速接球、扑救与二点、自由球竞速。专项场景只设置初始条件，之后统一由比赛引擎推进，不硬编码事件赢家。高速接球与扑救场景默认编号 `v4-scene-1` 可观察失误与脱手；修改编号可能得到成功控制等其他结果。

点击球员看任务、协作对象与目标线；点击事件回到发生时刻，查看决策或触球依据。“协同与转换”“触球与二点”可以筛选事件。播放器仍是生成后回放，尚未连接正式实时比赛发布流。

## 行为与因果

- 无球接应：两个队友分担斜后接应和向前接应，形成不同角度；短时保持分工，避开套上补位职责。中卫分配不同跟防对象。
- 压迫封线：分别安排上抢者、封线者和纵深保护者；封线目标位于持球点与实际对方接应人的线路上。组内任务一次提交，避免交接时出现两个上抢者。
- 套上保护：左侧套上有明确中场补位搭档；丢球或球转移后边卫实际回跑，达到原防守位置附近才释放补位。二点球任务不能抽走回追者和补位者。
- 攻守转换：只有对方实际控制球才切换球权；触球、封堵、脱手不直接认定转换。高压战术且丢球点附近有至少两名队友时启动最多 3 秒反抢，否则回撤；转换窗口 5 秒，得球方提供向前出口。期间再次易主产生新转换。
- 接球质量：球路与球员运动范围真实相交后，结合第一脚、相对球速、朝向、附近压力和体能计算控制概率。失误产生带速度的自由球，短暂触球冷却避免同一人瞬间反复接回。
- 扑救与封堵：门将能力影响射门接触后的控制质量；失败可形成脱手，外场封堵可产生反弹。反弹消耗本步剩余时间，允许后续连续触球，不自动分配给防守方。
- 二点争夺：双方各安排争球者和后方保护者，按球员与移动球实际接触时间处理。严格同一时刻触球使用能力权重与独立执行随机流，记录候选、权重及随机值，避免按主队编号固定获胜。

这些时间、距离和概率是原型规则，尚未经过真实足球分布校准。当前只支持左侧套上这一具体组合；不等同于任意位置的完整职责求解。移动自由球落点用短时预测，未实现完整空中落点模型。

## 状态与解释

`coordination.js` 纯规划每队协作组，保存接应分工、套上搭档、压迫组、转换阶段和二点任务。`tasks.js` 将组计划转成球员任务后统一移动。

`ball-control.js` 负责触球控制质量、反弹速度和场地边界交点。`engine.js` 按步内时间顺序处理球路、连续接触、球权和事件，状态保留 `nextTouch`、`transitionSerial`、`contestSerial`。二点事件通过 `contest.id` 和 `originEventId` 回溯首次失误、脱手或无人接应。

解释记录包括协作对象、实际封线对象、控制概率、来球速度、压力距离、随机判定、触球位置、争夺来源及最终控制结果。它们来自引擎当时的状态，不由播放器倒推赛果。回放保留接触关键帧、反弹速度和争夺标识；展示只使用当前播放时刻已发生的事件与比分。

配置、两个随机流、协作组、转换、自由球和触球冷却进入检查点。新版本拒绝 prototype.1 检查点，不做静默迁移。第一阶段源码备份在 `outputs/v4-before-stage2-20261117/`；真实联赛存档格式未发生变化。

## 验证与证据

- `npm run test:engine:v4`：28 项通过，覆盖协同唯一性、实际封线、补位持续、自由球不抽走补位、转换窗口、接球失误、脱手争夺、同时触球、断点恢复和回放一致性。
- `node --test test/engine-v33.test.js test/key-plays.test.js`：16 项旧引擎及回放定向回归通过。
- `node scripts/verify-v4-core.mjs`：48 段 180 秒战术组合完成；6 个专项场景检查点恢复与连续推进一致；600 秒片段 3376 帧、1376 事件，完整调试 JSON 35,927,597 字节。
- `node scripts/verify-v4-lab.mjs`：真实 Chrome 桌面及 390px 手机布局、生成、播放暂停、调速、历史回看、任务与解释、六场景、事件筛选通过，无页面异常或资源失败；截图人工查看。
- 证据在 `outputs/v4-coordination-20261117/`，保护文件哈希与本轮开始前备份比较一致，见 `preservation.json`。

没有跑全仓测试，没有部署或重启正式服务。组合模拟为本机未限资源功能检查，不是香港 2 核 2GB 容量验收，也不是比赛真实性或平衡验收。

## 尚未完成

完整比赛规则、越位、犯规、定位球、高球、半场、被动换人、真实球员能力与卡牌特性映射仍待实现；不得据本阶段结果自动接管正式比赛。主动换人仍不引入。

当前传球完成率、失误频次、射门进球与跑动量仍是未校准的原型输出。自由球、触球和转换的机制已贯通，后续需要专项统计与相同种子对照来校准参数。

调试帧含完整球员及协作状态，10 分钟约 35.9 MB，不能直接写进联赛 JSON。下一步可优先收敛规则与数据分布，再推进增量轨迹存储、真实数据只读适配和资源受限验证。
