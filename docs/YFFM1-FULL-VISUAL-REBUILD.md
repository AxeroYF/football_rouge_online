# YFFM1 全游戏视觉重建评估

日期：2026-11-11。范围：主界面、全部功能模块、比赛与卡片演出、整体 UI 以及响应式布局。电脑端优先，兼顾手机。

依据：当前项目源码、此前隔离账号的实测和截图、既有“专业经理桌面”偏好，以及近期 2K 适配和盾形卡改造。方案预览使用示意数据，不连接真实账号。本轮产出是评估与概念方案。

## 一、当前判断

当前已经有可用的战术板、盾形卡、开包、转播和俱乐部资源，适合进行完整的产品视觉重建。重点是建立一套覆盖所有模块的设计系统，再重建各页面的信息层级、布局与反馈。

目前最需要处理的共性问题：

1. 登录后的模式入口页与联赛经理工作台是两套体验。需要明确首次建队、继续经营和进入其他比赛的主次关系。
2. 联赛导航有 16 个同级入口，缺少与日常任务相符的分组。
3. 大量界面由同一份 app.js 拼接，主样式与各模块样式中存在多轮覆盖。继续逐页叠加样式，难以保证全站一致。
4. 日常管理、金属盾形卡、比赛直播、荣誉展示各有视觉语言，需要统一外围容器、字号、控件和操作反馈。
5. 桌面浅色与手机深色之间的品牌、组件与间距需要共同规范。2K 适配应成为基础布局规则。

最近已修复的战术板横向布局、完整球场、入口可见性和盾形卡切换，作为新设计的功能基线保留。

## 三、四套整体方案

### A：现代俱乐部经理——主推荐

定位：专业、清晰、适合长期经营。延续此前选中的经理桌面方向，重建为覆盖全站的成熟设计系统。

- 视觉：浅灰绿底色、墨绿品牌色、清楚的中文排版；暗色主题使用同一套组件与层级。
- 主界面：下一场比赛和备战动作最突出，下面组织积分形势、球队简报和近期赛果。
- 导航：常用功能直达；按俱乐部、球队、赛事、经营分组。分组调整需完整保留原入口。
- 数据模块：稳定的表头、数字对齐、统一筛选和选中状态；高密度与阅读舒适度可以兼顾。
- 战术：横向工作台，完整球场；预案、职责、原则与雷达使用同一套控件规范。
- 球员资产：盾形卡负责身份与稀有度，周边资料、强化与市场容器保持清楚、低干扰。
- 比赛：独立的深色观看场景，沿用品牌色和状态规则。
- 动效：保存、选中、模块切换和关键奖励有明确反馈。

适合当前 YFFM1 的高频管理、战术研究和长期经营。相对改造成本：中。主要风险：设计过于克制时，游戏氛围不足，需要在比赛、卡包和荣誉场景集中补足。

### B：职业赛事转播

定位：把每轮比赛塑造成有节目感的足球赛事。

- 视觉：深海军蓝、冰白和青色；简明的赛事标签、比分与时间排版。
- 主界面：以本轮比赛海报和对阵关系为中心，配合首发准备、积分形势与同轮赛程。
- 导航：比赛日、球队、球员、经营等横向主导航，模块内部使用清楚的二级导航。
- 数据模块：接近转播数据台的版式，强调赛程、表现与排名的关联。
- 战术：球队分析室语言，明确球场、比赛阶段和战术信息的关系。
- 球员资产：球员档案与转会资料的感觉，卡片材质保留，但避免每个界面同时使用强高光。
- 比赛：赛前片头、比分条、事件回放提示、半场和赛后统计成为主要表现空间。
- 动效：比分更新、关键事件与比赛阶段转换；常规表单保持简洁。

适合希望“打开游戏就像进入比赛日”的方向。相对成本：中高。主要成本来自比赛中心、赛前/赛后和其他模块之间的整体衔接；需要专门验证密集数据在深色界面的可读性。

### C：俱乐部年鉴

定位：围绕“这是一家属于你的俱乐部”，突出队史、经营与赛季积累。

- 视觉：暖纸色、炭黑、低饱和酒红或深绿；标题使用年鉴感排版，操作区使用清晰的中文无衬线字体。
- 主界面：俱乐部动态、下一场、赛季进展和当日报告，形成清楚的栏目。
- 导航：俱乐部、球队、赛事、球员资产、经营等栏目式组织。
- 数据模块：精确的线框、表格和留白，重视赛季对比与长期记录。
- 战术：现代工具台，采用相同品牌和排版，不增加装饰性纹理。
- 球员资产：球员档案、履历与盾形卡并列；强化和市场仍保持紧凑操作。
- 比赛：球队对抗海报与纪实风格战报；观看场景采用清楚的深色对比。
- 俱乐部和荣誉：队徽、球场、奖杯、年度纪录和赛季故事是最有辨识度的部分。

适合重视养成、队史和俱乐部归属感。相对成本：中高。主要风险：栏目式首页和高频操作页需要不同密度；过多纸纹和复古字体会影响表格阅读。

### D：竞技卡牌俱乐部

定位：强化组阵、收集、强化与对战的游戏感。

- 视觉：石墨深色、香槟金和有限的稀有度高光；以盾形球员卡为主要识别资产。
- 主界面：核心阵容、下一场比赛、资产变化与俱乐部动态。
- 导航：更紧凑的侧栏与清楚的模块入口，减少展示型画面中的界面噪声。
- 球员资产：更强的卡片浏览、选择、比较、强化结果与转会展示。
- 战术：小型盾形卡与战术配置一体，继续支持原磁贴偏好。
- 比赛：明显的对阵舞台与关键事件强调，数据与操作仍使用清楚的平面层级。
- 动效：开包、强化、稀有卡和夺冠演出承担主要视觉表现；普通操作使用轻量反馈。

适合希望提高卡片收藏和养成吸引力。相对成本：高。主要成本是素材、状态和演出的一致性；需要控制同时运行的特效数量、手机性能和缺少立绘时的视觉完成度。

## 四、选择建议

| 判断维度 | A 现代经理 | B 赛事转播 | C 俱乐部年鉴 | D 竞技卡牌 |
| --- | --- | --- | --- | --- |
| 长时间经营与管理 | 优先 | 良好 | 良好 | 需要控制视觉强度 |
| 数据与战术阅读 | 优先 | 良好 | 需设计紧凑工具区 | 需设计清楚的数据层 |
| 比赛日氛围 | 可集中强化 | 优先 | 纪实感强 | 对抗感强 |
| 俱乐部归属与队史 | 良好 | 赛事导向 | 优先 | 阵容与收藏导向 |
| 卡片与养成展示 | 清楚克制 | 球员档案导向 | 履历导向 | 优先 |
| 新美术与动效需求 | 较少 | 中等 | 中等 | 较多 |
| 相对改造成本 | 中 | 中高 | 中高 | 高 |

这是相同完整改造范围下的定性比较，尚未包含具体工期报价。素材重制范围、页面原型和功能状态清单确定后，再拆分工作量。

推荐 A 作为全站基础，比赛模块采用 B 的转播结构，俱乐部历史内容借鉴 C 的栏目组织。统一品牌、组件和交互规则，模块专属画面服务于各自的内容。

如果目标是让收集和强化成为第一视觉印象，则选择 D，并将卡片资源和演出制作纳入正式改造范围。

## 五、实施方式

### 第一阶段：定稿四个代表页面

经理首页、阵容战术、球员资产、比赛中心。四页分别验证信息密度、复杂操作、卡片与表单、实时观看。

交付物：品牌与主题规范、基础组件、桌面与手机原型、页面状态清单、素材清点。确认同一套设计能处理这些页面后，扩展到全站。

### 第二阶段：重建全局外壳和基础组件

统一导航、顶部状态、按钮、表格、表单、弹窗、通知与加载状态。先处理公共组件和样式层，逐步替换现有覆盖规则。

当前 DOM/SVG 前端可以承接上述四套方案。视觉重建不以更换框架或比赛引擎为前提；页面呈现、UI 状态与业务请求需保持清楚的边界。

### 第三阶段：迁移全部功能模块

1. 总览、日程、积分榜、赛事页与收件箱。
2. 阵容战术、球员资料、背包、强化与巨星之路。
3. 市场、商店、卡包、交易确认和奖励结果。
4. 比赛、TV、历史战报、俱乐部、赞助和荣誉。

每批验证原有操作和状态，再移交下一批。

### 第四阶段：统一场景演出与适配

开包、强化、进球、赛后、夺冠使用统一的动效节奏。提供减弱动画选项；卡片动画与普通操作分开控制。补齐空状态、保存失败、网络中断、未开放功能和长内容。

## 六、必须保留的产品约束

- 战术板和替补席的拖拽、换人、职责、预案、自动选人及自动保存逻辑。
- 磁贴/盾形卡设置、现有卡片等级与强化语义、已获得的卡片和俱乐部资产。
- AI 对战和玩家镜像保持直接可见，原收费与休赛期限制有明确提示。
- 批量模拟和服务器模拟保持当前屏蔽范围。
- YFFM1 当前游戏范围与比赛逻辑；主界面信息整理不新增已经清理的模式入口。

## 七、验收基线

- 桌面检查 1366×768、1440×900、1920×1080 和 2560×1440；补查 2K 常见 125% 与 150% 缩放对应的可用尺寸。
- 战术默认视图完整显示球场、可操作的替补与原则入口，球场无内部翻页或滚动；展开详细指令有明确的布局规则。
- 资产列表、市场和历史记录保留自然的纵向浏览。手机 320/390 宽度无整页横向溢出。
- 常用文字、按钮目标和长球员名可读；主要操作不依赖悬停；键盘焦点与错误提示明确。
- 明暗主题、选中、禁用、加载、空状态和失败状态逐一检查。
- 高频刷新保留草稿、选中卡片、滚动和焦点；视觉偏好切换不写入球队或比赛数据。
- 在真实设备上测量动画和页面流畅度，单次截图不作为性能结论。

## 八、本轮原型

四套方向均可切换经理首页、阵容战术、球员资产、比赛中心；球员卡支持资料摘要与位置筛选。采用示意队名、能力、比分与赛程，卡面人像为概念符号。

概念预览用于选择全局视觉方向，不代表全部功能页面已重新实现。实际改造以完整页面与状态清单为交付依据。

本轮概念预览已检查四套方向的桌面页面切换、球员选择与位置筛选、明暗主题和窄屏横向溢出；脚本语法检查通过。验证数据在 outputs/visual-rebuild/verification.json，概念截图在同目录。本轮未修改游戏的运行代码和真实存档。
