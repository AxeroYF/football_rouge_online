# 客户端界面与同步减负 · 2026-09-28

用户授权“开始优化”，本轮实现已在工作树验证，尚未打包、部署或推送。服务器确认版本仍为 R41。此前交付的 Windows 0.1.6 安装包没有覆盖，本轮 Windows 源码改动需后续生成新版本安装包才能交付。

## 已实现

- 新增自适应状态轮询：正常 5 秒；连续 60 秒无指针、键盘、滚轮操作后改为 15 秒；自己的活动挑战或远征移动保持 5 秒。重新操作、切回窗口、Store 接收到非轮询更新后合并为 250ms 后同步。
- 后台标签暂停轮询；失败采用 10、20、30 秒退避；同一时刻最多一个轮询请求，进行中的刷新请求合并为一个后续请求。
- 编队批量操作每栏首次显示至多 36 张卡片，联赛注册可选栏首次 36 张，点击继续显示追加 36 张；注册栏最多 23 人保持完整。筛选仍针对全体球员，全选包括尚未显示的筛选结果，已有本地草稿、拖动、校验与统一保存继续生效。
- 联赛注册记录当前渲染基线，避免首次无变化轮询重绘中断拖动。
- Windows 启动窗口紧凑化、允许缩放，游戏窗口按主屏工作区限制尺寸，恢复上次关闭时保存的尺寸和最大化状态。错误状态不再同时显示正在连接的引导文案。构建白名单已加入 window-layout.mjs。

## 收益及边界

稳定空闲阶段状态请求从约 12 次/分钟降至 4 次/分钟，减少约 67%；不代表服务器 CPU 总量降低 67%。后台停止同步的行为原本就已存在。

本轮服务器接口和权威结算不变。完整状态仍由服务器构建后计算字段哈希；尚未实现服务器按模块版本跳过构建。这需要覆盖所有服务的写入、定时结算和可见性变化后才能安全启用，不能直接按 world.revision 缓存，否则可能漏掉账户和时间驱动更新。

本轮主要减少请求和浏览器卡片 DOM 数量。筛选、拖动草稿与展示继续在本地运行；尚未新增 Worker 或将比赛、抽卡、交易结算移至客户端。
