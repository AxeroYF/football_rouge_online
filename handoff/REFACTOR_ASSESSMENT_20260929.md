# 项目重构完整评估 · 2026-09-29

## 结论与评估范围

建议继续使用当前原生 ES Modules + Node 单体服务，采取小步提取、保持协议和存档兼容的模块化重构。优先治理测试入口、运行观测和读写边界，再统一前端刷新，最后处理存储和比赛引擎。现在整体换框架、引入微服务或同时换数据库会扩大验证范围，无法直接解决已有热点。

基线：用户确认 R43 已部署；工作区 1257 个已发布运行文件与 R43 哈希一致。本轮评估不修改运行架构、依赖、玩法或发布包。Windows 0.1.7 安装包与后来加入源码的 PNG 下载支持属于不同交付状态，不能混称已安装功能。

覆盖客户端装配与窗口、卡片与名单、服务端业务装配/HTTP、经济结算和持久化、比赛引擎、地图模块、桌面壳、测试与热更新。采用全仓静态扫描和重点路径代码审阅，并补跑遗漏测试；未采集线上 CPU/内存火焰图，不声称已完成每条玩法路径的形式化正确性证明。性能收益需要在正式服务器同配置隔离环境测量。

## 必须保留的业务边界

1. 球员定义 ID、实际卡实例 ID、代表卡不是同一概念；出售/合卡不能错误映射回同名卡。强化保留主卡身份，真实总评不能重复加成。
2. 联赛注册最多 23 人，不强制位置；无操作沿用，初次初始化留守首发；联赛进行中锁定；联赛体力伤病独立，不能串入远征/留守。
3. 训练/球探/联合考察的金币支付、退款、完成奖励与幂等回执由服务器决定。前端本地计算只承担展示、筛选、预览。
4. 双方交易/求购/地块交割必须原子化，检查当前有效占用；不能让历史任务再次锁死地块。
5. 联合考察双方各出球探、各付一半，结果独立随机；地图考察点轮换。重构时固定旧行为，不夹带数值平衡调整。
6. 时间驱动系统覆盖跨天、离线恢复、服务器停机、压制暂停、旧存档迁移；测试使用可注入时钟。
7. 卡画、存档、凭据不进入公开 Git；重构不能改变发布文件原始换行与校验哈希。
