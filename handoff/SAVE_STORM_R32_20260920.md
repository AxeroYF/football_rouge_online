# R32：重复全服保存导致卡顿修复（2026-09-20）

基于 R31，5 个更新文件、无新增运行模块。仅本地验证打包，未远程部署。

## 现场判断

用户最新日志显示 R31 已运行：存档由约 92MB 降至约 40MB，压缩已生效。本次无新 OOM，系统仍有约 598MiB 可用内存，服务 RSS 约 660MiB；但磁盘持续约 42MB/s 写入，本机健康接口和主页均 8 秒超时。主要排查方向是同步计算与反复全量保存占满主线程，不能把本次现象继续归为单纯内存耗尽。

## 已复现并修复

1. 建筑状态查询发现任意未完工建筑就全服保存。改为仅处理预测已到期的未暂停建筑，或迁移没有生产进度的旧建筑。经济变化和正常生产推进仍刷新预测。
2. 豪门远征等待正在比赛的防守方时，每秒复制全世界并保存两次。改为无变化等待直接返回；每轮仍核验归属、保护期和活跃状态。比赛解锁后正常开战，领地失效则正常跳过。
3. 被远征压制暂停的治疗任务反复被判定到期，但结算跳过，导致经济一直处于待保存状态。到期判断现在与暂停结算条件一致；解除压制后恢复。
4. 保存日志新增 count、totalBytes，分别记录进程启动以来成功保存次数与累计字节，不增加存档扫描。进程重启后从头统计。

这三条是本地复现的确定缺陷，与现场写盘和比赛负载吻合；没有取得线上堆栈，不能声称所有 504 根因都已消除。全量同步保存和部分全世界事务快照仍存在。

## 部署

上传 tar.gz 和同名 .sha256 到 /home/admin，然后分别执行：

```bash
cd /home/admin
```

```bash
sha256sum -c yellowdogs-hot-update-20260920-r32.tar.gz.sha256
```

```bash
tar -xzf yellowdogs-hot-update-20260920-r32.tar.gz
```

```bash
cd yellowdogs-hot-update-20260920-r32
```

```bash
sudo bash update.sh --check
```

```bash
sudo bash update.sh apply
```

看到 Installed: 20260920-r32 后刷新游戏。无需重装 Windows 或安卓客户端。保留安装器给出的备份路径；回退使用更新器恢复匹配代码与存档，不能仅覆盖旧代码。
