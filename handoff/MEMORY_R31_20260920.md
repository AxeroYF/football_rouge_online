# R31：大历史存档内存修复与 504 排查（2026-09-20）

现场已运行 R30，R31 基于完整 R30 升级。16 个文件，新增 4 个模块。本包仅本地构建与验证，未部署。

## 现场证据与结论

- 用户日志明确记录 OOM killer 杀进程，多次内存峰值约 1GB；R30 运行中 RSS 曾达到约 924MB。服务仅 12 账号、无活动比赛时，存档仍约 89MB，保存约 0.9 秒，事件循环多次阻塞 3–4 秒。
- 用户只读统计：battleHistory 40,805,470 字节，scouting 28,312,587，enhancement 6,321,005，cardManagement 3,252,895；世界 eliteRaids 7,454,817。此前新账号、无历史的容量测试未覆盖此负载，不能用于判断现网内存安全。
- 原来整份 JSON.stringify 生成巨型字符串，写入再分配编码缓冲；常驻历史在业务 structuredClone 中再次放大。已有回执条数治理无法解决历史单条体积。
- 19:29 后主线程监控停止，20:00 停服也超时。长时间阻塞的确切入口尚未复现，不能宣布 504 全部根因闭环。不能只提高代理超时或内存上限。

## 修复内容

1. 原子保存改成分块 JSON 输出，维持临时文件、fsync、rename 和失败清理。文件格式仍为 JSON；不延迟确认业务成功，不使用后台异步写覆盖新状态。
2. 已结束的普通/联军、豪门挑战、豪门远征、友谊赛战报详细广播使用 gzip 无损归档。摘要保留，详情 API 按需还原，不缓存展开后的大对象，不删已有比赛事件或战报。
3. 已领取的旧球探任务保留选择标识和领取结果，移除未选候选副本；领取结果无损压缩，重复领取仍返回原结果，选择不同卡仍拒绝。进行中、未领取任务不压缩、不删除。
4. 强化历史回执的结果快照无损压缩，保留签名与重试返回值，未修改收费或概率。
5. 启动读入后、其他迁移之前完成历史压缩；运行维护每轮最多检查 32 条待处理记录，以引用替换回滚，保存失败恢复原对象。小记录和压缩无收益的记录保持原样；不新增强制历史删除。
6. 独立诊断线程在主线程超过 15 秒无心跳时记录 `[campaign-stall]`，含阻塞时长、运行阶段与 RSS。阶段包括 state/save/persist 和各比赛推进类型；不含账号、令牌。不自动杀进程、不自动改结果。线程堆限 16MiB，正常运行只检查共享时间戳。

## 部署

上传 tar.gz 和同名 .sha256 到 /home/admin 后逐行执行：

```bash
cd /home/admin
sha256sum -c yellowdogs-hot-update-20260920-r31.tar.gz.sha256
tar -xzf yellowdogs-hot-update-20260920-r31.tar.gz
cd yellowdogs-hot-update-20260920-r31
sudo bash update.sh --check
sudo bash update.sh apply
```

看到 Installed: 20260920-r31 后刷新页面或重新打开客户端，无需重装 Windows 或安卓客户端。首次启动会压缩已有历史存档。更新器保留配套文件和存档备份；回退必须使用更新器恢复匹配的旧版本存档，不能只替换旧代码后继续读取压缩格式。健康检查失败会自动恢复匹配备份。

观察命令分别执行：

```bash
sudo journalctl -u yellowdogs-rougelite -n 80 --no-pager
```

```bash
sudo journalctl -u yellowdogs-rougelite --since '10 minutes ago' --no-pager | grep -E 'campaign-runtime|campaign-memory|campaign-stall'
```

重点比较 save.bytes/save.durationMs、RSS/heapUsed、事件循环延迟。如仍 504，保留 campaign-stall 行；需要它定位尚未复现的长阻塞入口。历史详细数据仍保留，未来规模增长仍需观察；复杂事务的全世界快照和全量同步保存尚未全面消除。
