# 手机横屏 UI 审计与优化路线 · 2026-09-09

## 结论与范围

当前网页的手机横屏问题是全局可用高度、导航布局、滚动/焦点和复杂页面结构共同造成的。不是 780×360 设置错误，单纯缩放网页或套 Android WebView 无法解决。

本轮只新增隔离审计脚本、截图及报告；未修改游戏运行代码、正式服数据或安卓客户端。安卓开发保持暂停。测试服务仅监听本机，使用临时目录内的虚构账号。

Chrome 移动模拟：780×360、740×320，DPR 3、触摸模式。实际浏览器覆盖地图、编队、战术、商店、豪门目录、赞助、背包、研究、卡管理、强化、奇观目录、互动主页；780×360 另测训练、球探及登录。共 32 份页面/诊断记录，含 1440×900 桌面对照和四个临时高度修正诊断。没有 pageerror 不代表 UI 合格。

导航被挤出时，脚本会程序触发入口以继续检查内部页面；这不算导航可用性通过。测试球员阵容/资源是夹具，不能用测试截图判断正式服球员搭配或经济数据。

### 不是所有“在屏幕外”的内容都是缺陷

列表允许在自己的容器内滚动。这里的硬问题是窗口外壳已经超出实际屏幕、操作区域不可见，以及滚动/焦点移动了整个页面。report.json 的 outside 仅是几何标记，不能把滚动列表里每个暂时不可见项目都算故障；smallControls 也包含隐藏的原生复选框，实际可点击 label 要另验。

### 已有能力与待验收项

普通设施/奇观说明已有触摸点击入口，并有关闭按钮。战术拖拽已有 pointer 事件，不能仅凭手机截图认定没有触摸支持。

本轮没有逐一实测：三选一最终领奖、完整比赛战报、交易填写与双方确认、全部资源明细和每项科技二级页，以及真机双指缩放/键盘/卡拖动。它们沿用相同布局有风险，下一轮必须补测，但不标记为已证实的业务故障。本轮没有发起正式服比赛或交易。

## 建议实施顺序

### 第一批：让整款游戏在短横屏内可操作

1. 统一网页可用高度和安全边距，考虑浏览器地址栏、输入法、横竖屏切换；修复页面被焦点推移。
2. 新增短横屏布局条件，覆盖780×360和740×320，不再仅以680px宽判定手机。
3. 调整顶栏为紧凑导航；所有功能都有明确入口，选中状态与返回入口可见。
4. 玩家列表/通知/地图工具统一收放，互相不盖住操作；通知直接处理保留。
5. 登录、建队和通用窗口先统一到新布局规范。

验收：视口内能找到打开、返回、关闭与主要操作；打开/关闭各窗口页面不偏移；底部工具可达；不用缩小浏览器比例才能玩。

### 第二批：逐页提升实际可玩性

优先战术板、编队及卡管理，再商店/豪门/三选一，然后设施/互动/科技/战报。

战术核心行为保持原规则：默认/领先/落后站位、远征/留守、羁绊、体力红线、保存逻辑继续共用；改的是信息展示与触摸入口。不要把手机战术板分叉成另一套规则。

验收：玩家在首屏可以理解当前页面并开始主要操作；列表和详情分别滚动；拖动球员不误触页面滚动；买卡、训练、交易、挑战的费用与确认按钮同时清晰可见。

### 第三批：真机复核后再恢复 APK

网页逻辑/布局统一生效于 Chrome 与 Android WebView。Android 客户端后续只负责系统栏、安全区、键盘、返回、更新等平台行为，清理与网页重复的 CSS 覆盖，避免两端逐渐不一致。

最终矩阵：780×360、740×320、较大手机横屏、390×844竖屏应急，以及1440×900/1920×1080桌面对照。手机模拟负责布局复现；三星真机负责键盘、手势、GPU和恢复前台，不用模拟器结果替代真机结论。

审计输出目录：`outputs/mobile-landscape-audit-20260909/`。
