## 已确认的产品规则

### 回收

用户已确认首版价格。回收金额 = floor(评级估值 × 20% × (1 + 强化等级 × 10%))；训练成长不加价。

| 评级 | 估值 | +0 回收 | +4 回收 | +8 回收 |
| --- | ---: | ---: | ---: | ---: |
| C | 400 | 80 | 112 | 144 |
| B | 2,000 | 400 | 560 | 720 |
| A | 10,000 | 2,000 | 2,800 | 3,600 |
| S | 50,000 | 10,000 | 14,000 | 18,000 |

X 回收按传奇 S 计价。后台可以修改评级估值、回收比例、每级强化加价和开关。整数运算后向下取整，不使用训练总评重新定价。批量回收最多 100 张，预览显示总金额、素材和首发影响；素材具有成长时额外提示。

### 汰换

- 必须是 5 张不同实例、同一评级的素材；可以是同名球员的独立副本。
- C → B、B → A、A → S。S/X 与 isX 传奇卡不可作为素材。
- 候选来自五张素材所属国家与俱乐部的并集，并且恰好高一级。国家和俱乐部满足任一项即可。
- 候选按球员定义 ID 去重，等概率抽取；相同国家、相同俱乐部和同时命中两者均不增加权重。
- 国家／俱乐部优先使用已上线定义，已退役定义才使用保存卡的字段；统一 Unicode、空白和大小写。空值及无俱乐部等占位信息不组成候选池。
- 不回退到全局随机池。无候选时保留所有素材，要求更换素材。
- 预览列出全部可能产出及每名 1/N 的概率；产出独立新卡，+0、无训练成长，加入留守。保留产出球员自身的基础特性，不继承素材强化特性。
- 预览至确认期间若素材、阵容、价格配置或候选目录变化，拒绝旧预览并要求重新确认。

### 公开市场

- 玩家自行填写整数金币价格，一张实例一条挂牌；首版不收挂牌费或成交手续费，不自动到期，不支持直接改价，下架后可重新挂牌。
- 上架时从玩家可用 roster 中移出，完整卡片由挂牌托管；市场浏览和“我的挂牌”展示托管卡。
- 挂牌期间不能训练、强化主卡／副卡、回收、汰换、重新挂牌、后台转让或参加新比赛。旧页面继续提交也无法找到该卡。
- 下架与成交均交回完整卡片，保留强化、训练成长、特性、体力及伤停状态；进入接收方留守名单。
- 玩家不能购买自己的挂牌；后台重新校验挂牌状态、价格、金币和实例唯一性。抢购只有首个有效请求成交，其余返回已售出。
- 原始建队卡可能没有独立实例 ID：上架／后台转让时补为新实例 ID，保留球员定义与全部成长，以免买家同名初始卡发生 ID 碰撞。
- 价格技术上限 1,000,000,000 金币；仅接受正整数。

### 转出边界与阵容

- 锁定、训练中、待绑定强化特性的球员不可转出。训练任务同时检查球员标记及任务记录。
- 球队正参加攻击或防守比赛时，暂不允许转出本队球员；等待整场挑战结束，以保留两回合快照边界。
- 首发允许转出，预览／后台确认提示阵容影响。复用 repairTacticsLineups：保留其他首发和三套站位，仅本编队补位，无替补时保留空位。
- 已完成训练的结果在球员转出时收起，避免原设施继续引用已转出的卡；未完成训练必须先取消或完成。
- 获取／下架后的球员可能成为同名最强代表，按当前共享规则修复阵型。库存独立实例始终保留，管理窗口不采用球队页面的代表卡去重。

### 后台代办交易

用户确认要可执行的后台交易，玩家端暂不开放定向交易。管理员选择卖家、买家、独立卡片、金币价格，填写原因并确认后，同时转卡和划转金币。

只有 operator / superadmin 可执行和配置回收；content / readonly 可查看但不能交易或改价。沿用同一转出边界，挂牌卡需先下架。交易日志包含双方、球员、价格、管理员、原因和时间。

## 保存与一致性

account.cardManagement 保存请求回执、挂牌（含托管卡）和最近 100 条操作记录；world.cardManagement.config 保存可调价格，世界 hydrate 明确保留该字段。旧账号按需初始化，无需手工修改存档。

请求使用 requestId + 参数签名；相同请求重试返回原结果，不重复扣卡／金币或重新抽取。客户端网络失败保留原请求 ID，账号切换后忽略旧响应；服务端预览签名校验材料与上下文变化。

买卖双方、卡片托管和业务记录在现有同一个 campaign JSON 原子保存中落地，保存失败回滚内存参与方与世界；使用单 Node 进程的同步提交段避免挂牌重复成交。原管理员审计文件独立保存；双方存档内仍保留同一次交易的审计数据，审计文件失败后的重试不会再次划账。

- 前端：新增 `client/cards/card-market-view.js`，管理双栏模板、独立筛选／排序、报价输入和确认模板；`card-management-controller.js` 负责两侧滚动追加、预览、购买／撤回、账户隔离和幂等重试。菜单正式开放出售，汰换继续禁用。模块与样式入口版本为 `20260906-market-v1`。
- 仓库点击卡面选择，点击卡名查看完整详情。顶部显示所选卡、可输入整数金币价格（1–1,000,000,000），金色“挂牌”按钮请求后端报价，再由“确认挂牌”执行。切换筛选、返回菜单保留卡和价格；改选另一张卡清空价格，避免误用上一张的定价。报价缺少 `sourceSquad` 时拒绝继续，提示重启服务。
- 左侧可购买其他人的挂牌、撤回自己的挂牌；“我的挂牌”快速筛选。购买确认展示金币和卖家，撤回确认展示原编队。金币不足不允许购买，已成交／下架或旧报价由服务端拒绝，错误保留在确认框内，返回刷新或重新预览；网络失败重试复用请求 ID。
- 挂牌卡退出持有卡列表并托管，期间不可编队、训练、强化、回收或汰换；训练、锁定、待绑定强化特性和进行中比赛的限制延续既有业务规则。回收多选中已被挂牌的实例自动移除，其他选择保留。
- 后端在报价与挂牌记录中保存 `sourceSquad`。远征、留守均可挂牌；`receive` 接受返回编队参数，取消挂牌按原编队恢复，返回结果包含 `squad`。记录可持久化，旧实例生成新 ID 后也能正确返回。返回编队不会挤走已有首发，缺位沿用当前补位逻辑。购买与汰换产出仍进入留守。
- 历史兼容：此前已存在且未记录 `sourceSquad` 的挂牌按旧规则回留守，无法从缺失字段还原原编队；没有修改真实账户或存档。新挂牌均记录原编队。
- 验证：新增 12 项前端测试、6 项后端测试；卡管理 UI 28 + 业务 24 + 窗口标准 5 = 57 项相关检查通过。完整 `npm run check` 486 项通过（61 预检 + 356 主测试 + 69 Three）。离线 CSS 8,652 项通过，覆盖两主题、1920/1600/1366/1180/820/560/390 宽度，新增市场、选卡、确认、空状态 4 份真实模板；不是浏览器截图验收。输出在 `outputs/card-management-review/market-full-check.log`、`market-targeted-check.log`、`style-checks.json`。
- 人工验收：用户自行重启 4370 → Ctrl+F5 → 球员卡管理／出售 → 右侧选择远征卡并定价 → 确认挂牌 → 左侧“我的挂牌”撤回 → 编队里确认返回远征；另用第二账户购买并核对金币及留守归属。服务与浏览器未由代理启停或操作。
## 挂牌交互与最低限价 market v2

用户本轮要求：支持拖动、双击挂牌；价格放在确认挂牌悬浮窗口；不同强化和能力有最低限价。用户通过问答明确采用下列首版公式。

### 最低限价

`ceil10(评级估值 × 0.5 × (1 + max(0, 基础能力 - 评级基准) × 0.05) × 强化倍率)`。

- 评级估值沿用后台配置：C400、B2000、A10000、S50000；X 按 S。后台调整评级估值会同时影响回收价和市场限价，后台说明已注明。
- 评级能力基准：C75、B80、A86、S90。优先使用保存的 `baseOverall`；旧卡缺失时用总能力减去当前强化能力加成，避免强化重复加价。基础能力按显示整数取整；训练属性、体能和伤停不额外调价。
- 强化倍率复用已接入的 `S4_ENHANCEMENT.cardValueMultipliers`：1、1.7、2.7、4、6、9、13、19、28。
- 以 BigInt 精确计算，最后向上取整到 10 金币；挂牌上限维持 1,000,000,000。价格必须为整数，缺失能力或无有效限价不可挂牌。

| 卡片基础能力 | +0 最低价 | +4 最低价 | +8 最低价 |
| --- | ---: | ---: | ---: |
| C75 | 200 | 1,200 | 5,600 |
| B80 | 1,000 | 6,000 | 28,000 |
| A88 | 5,500 | 33,000 | 154,000 |
| S90 | 25,000 | 150,000 | 700,000 |

### 交互和安全边界

- 单击仓库卡只更新选中光效／标记和顶部按钮，不重建卡片 DOM。双击、拖到市场或点击顶部挂牌都会请求只读报价，在同一个原生模态窗口内编辑价格。
- 输入默认最低价，返回窗口保留该卡的价格草稿；改选其他卡使用其自己的最低价。低于最低价／非整数／超上限禁用确认按钮并显示错误；支持回车确认，输入法组合时不误提交。
- 卡牌拖动使用受控的实例 ID 和专用 DataTransfer 类型，检查本仓库来源及可用性。只在拖入市场时出现“松开卡片以挂牌”；离开、取消、关闭或重绘清理拖动状态。训练／锁定／进行中比赛等既有限制不变。
- `/api/campaign/cards/preview` 的 list 允许暂不传价格，此时返回最低价、`minimumPrice`、原编队、`listingTerms` 与报价。`listingTerms` 绑定卡片／配置／阵容／编队，与价格分离。确认时按输入价格获取报价，条款变化则更新悬浮窗口并要求再次确认；最终 `/list` 必须明确传入合法价格并再次校验。旧后端缺少新限价字段时提示重启，禁止继续挂牌。
- 写请求失败后保留原提交参数，重复确认直接重试同一个 requestId，避免已成功托管但响应丢失时重新预览已转出的卡。预览／提交期间冻结输入，保留跨账户和关闭／重开隔离；回收多选会移除已挂牌卡，其他选择保留。
- 新限价只约束新挂牌；已有挂牌不被修改，购买按已展示的原价格成交。管理员代办交易不增加市场限价限制。
- 远征和留守均可挂牌，撤回回原编队；买家接收进留守。以前未记录原编队的旧挂牌兼容规则与 v1 相同。
