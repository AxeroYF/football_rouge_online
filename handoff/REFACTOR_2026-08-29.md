# Rougelite 模块化重构记录

日期：2026-08-29

## 本轮目标

在不改变玩法数值、HTTP 接口和存档格式的前提下，建立后续模块化重构所需的基础边界：

1. 业务参数按领域集中管理。
2. 足球显示字典只保留一个来源。
3. 前端鉴权请求从建队页面中分离。
4. JSON 存档读写从 CampaignService 中分离。

## 已完成

### 共享配置

- shared/config/economy.mjs：初始金币和金币流水保留数量。
- shared/config/challenge.mjs：常规时间与加时链数、比赛时间、回合冷却和挑战总时长。
- shared/config/draft.mjs：选秀人数、四线最低人数、品级和位置抽取权重。
- shared/config/maritime.mjs：最大航程、方向扇区、采样距离、最短航线和海岸吸附距离。
- shared/football/labels.js：四线名称、球员位置、比赛心态和比赛打法中文名称。

### 前端 API 边界

- 新增 client/core/campaign-api-client.js。
- 统一管理 token 的读取、写入、清除、Authorization 请求头和 API 错误。
- campaign-entry.js 不再直接实现 fetch 和 localStorage 鉴权逻辑。
- 退出登录通过启动上下文中的 clearSession 清除会话。

### 后端存档边界

- 新增 server/infrastructure/json-campaign-repository.mjs。
- JSON 文件检测、解析、目录创建和保存已从 CampaignService 中移出。
- CampaignService 支持注入 repository；原有 dataPath 构造参数仍兼容。
- 存档版本保持为 3，数据结构没有变化。

### 兼容处理

- campaign-service.mjs 继续导出原有金币、选秀和挑战常量。
- campaign-match-engine.mjs 继续导出原有比赛时长与链数常量。
- campaign-broadcast.js 继续导出 SECOND_LEG_COOLDOWN_MS。
- 现有服务器路由、前端启动事件和存档字段没有改变。

## 下一阶段建议

1. 建立显式存档 migration 管线，将构造函数里的旧账号、金币、地块 ID 和球员库迁移移出。
2. 保留 CampaignService 门面，内部先拆 EconomyService 和 ChallengeService。
3. 将实时挑战定时推进从 server.mjs 拆到独立 challenge scheduler。

## 第二阶段完成项

### 显式存档迁移管线

- 新增 server/infrastructure/campaign-save-migrations.mjs。
- 迁移步骤现在按固定顺序声明：账号默认值、金币结构、领地 ID 别名、球员目录。
- 世界恢复、碎片小国旧 ID 合并、主场和战报 ID 修正均已移出 CampaignService。
- 每次加载会返回实际执行的迁移步骤；只有发生迁移时才立即保存。

### 独立经济服务

- 新增 server/application/economy-service.mjs。
- 新账号初始化、旧账号金币迁移、收入、支出、余额校验和流水上限全部由 EconomyService 负责。
- CampaignService 的 adjustGold 和 spendGold 保持原接口，只负责委托和持久化。

### 地图颜色领域逻辑

- 玩家颜色表迁移到 shared/config/map.mjs。
- 颜色分配算法迁移到 server/domain/player-map-colors.mjs。

### 独立挑战调度器

- 新增 server/scheduler/challenge-scheduler.mjs。
- server.mjs 不再直接维护 dirty 状态、推进定时器和保存定时器。
- 调度器继续保持每次最多推进一场比赛、每场最多一条控球链，并只保存发生变化的数据。
- 运行时环境变量和上下限保持不变。
