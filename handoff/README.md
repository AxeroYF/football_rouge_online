## 模块化边界

- `CampaignService` 保留兼容门面，存档、迁移、经济、挑战与调度已经分层。
- `client/core/campaign-store.js` 是前端服务器状态发布边界。
- 地图数据、坐标和地块展示分别位于 `client/map/`。
- 地块选择/主场、跨海测绘和挑战直播分别位于 `client/territory/`、`client/maritime/` 和 `client/challenge/`。
- `app.js` 已从重构前 1116 行降至 718 行，当前主要负责 Leaflet 图层、城市、应用外壳与模块装配；滚轮惯性和缩略地图已分别拆到 `client/map/inertial-wheel-zoom.js`、`client/map/campaign-minimap-controller.js`。

### S4 球员卡画流程

- 卡画由 `assets/data/s4-player-profile-registry.json` 按球员 ID 驱动。

- 新 S4 资源包可通过 `node scripts/import-s4-player-profiles.mjs <S4解压目录>` 导入，再执行同步或重建目录。
- 当前已有 245 个 S4 精确映射，哈希头像保存在 `assets/player-profiles/s4-imported/`，没有 ID 映射时不会自动误配。
