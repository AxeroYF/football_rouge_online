## 服务器实时比赛与 S4 播报密度（本次更新）

- 地块挑战不再在发起时一次性计算两回合和最终胜负。创建挑战时只建立第一回合 V2.1 会话，公开响应中的 `battle` 为 `null`。
- `server.mjs` 使用与 S4 相同的低压力切片原则：默认每 100ms 检查一次，但每个切片最多只推进 1 场比赛的 1 条控球链；墙钟进度未到下一条链时不做比赛计算。
- 第一回合真实完成后才进入 3 分钟整备；第二回合随后实时创建。只有第二回合（含必要的加时/点球）真实结束后才生成总赛果并改变领土归属。
- 前端不再按“最终事件总数 / 120 秒”均匀回放预计算事件，改为每 1000ms 拉取服务器已生成的直播快照。播报事件规则仍与 S4 V2.1 一致，密度和安静间隔由真实控球链推进决定。
- 新增 `GET /api/campaign/territory/challenge?id=...`。进行中只返回当前回合、实时比分和已生成事件，不返回 outcome；结束后才返回精简赛果。
- 活动比赛每 5 秒批量持久化进度。V2.1 随机数游标 `rngState` 一并保存，服务器重启可 O(1) 恢复，不需要从开球重新模拟；前端刷新后会恢复自己的后台比分卡。
- 世界存档 schema 为 3，`world.activeChallenges` 可保存实时会话。
- `npm run check`：32/32 通过，包括每切片最多一条链、赛前不泄露结果、终场后结算、随机数确定性续赛和前端固定 S4 快照节奏。
- 浏览器交互验收按用户要求由用户自行执行。
