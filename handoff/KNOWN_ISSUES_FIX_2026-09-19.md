# 四项已知交互问题修复 · 2026-09-19

状态：本地源码完成，未打包、未部署；包含在前一批性能优化之后。原 R12 包不变。

## 修复
1. 强化：原先每次选卡、移出槽位或同步状态都设置整个内容区 innerHTML，导致延迟卡面被销毁并重新排队加载。改为按卡片 ID 保留节点，更新变化内容；未变卡面、滚动容器保留，特性/训练标签仍更新。
2. 汰换：同样由整窗重建改为局部 DOM 更新，仓库按卡片 ID 匹配；保留未变卡面和滚动。金币变化不触发汰换详情读取（市场继续保留钱包相关刷新）。滚动监听复用，避免节点保留后累积监听。
3. 豪门行军：默认 preferCanvas 地图上，豪门路线未指定 renderer/pane，创建了位于 overlayPane 的整屏 Canvas，高于 territoryPane；即使路线 interactive:false，Canvas 元素本身仍挡住底下的领地。改用专用 SVG 路线层并设置 pointer-events:none，豪门图标仍保留原点击入口。
4. 联军借调：列表按球员 ID 局部更新，保留滚动；读取期间不重复发请求，写入开始使旧读取失效；修正使用 attackBlocked 推断宵禁变化造成的重复刷新，改为比较服务器时间对应的宵禁状态。管理页 GET/POST 请求轻量详情，省去不用的完整战术数据；默认接口仍保留战术数据供原调用方使用。借调等待期间立即禁用借调/归队按钮。
