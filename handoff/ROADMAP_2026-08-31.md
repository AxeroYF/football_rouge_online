# 黄狗风云开发路线图

更新时间：2026-08-31（Asia/Shanghai）

本文是当前唯一有效的总路线图。ROADMAP_ADMIN_2026-08-29.md 保留为 Admin 规划的历史底稿，若两者冲突，以本文为准。

## 产品方向

黄狗风云不应做成传统的即时操作 RTS。更准确的定位是：

大地图远征经营 + 异步战略推进 + S4 V2.1 自动比赛模拟。

玩家的核心决策是组建球队、安排远征、选择路线和目标、管理体力与设施、承担天气和随机事件风险，并通过真实耗时推进世界状态。比赛本身继续由成熟的足球引擎和电视台承担。

## 已完成基础

- 欧洲与南美大地图、1470 个地块、邻接挑战、跨海路线、永久主场和领地状态。
- S4 V2.1 比赛引擎、两回合挑战、加时/点球、服务器实时推进和成熟电视台。
- S4 战术板、阵型与阵容保存。
- 以 S4 Admin 为底座重做的黄狗风云后台：登录、RBAC、审计、任务、球员维护、26 项属性、批量制卡、暂存发布和卡画工作室。
- 统一 YDL 球员库：842 名球员；卡画注册表 386 条；注册文件缺失 0、孤儿注册 0。
- 标准球员卡库与接口，球队管理、Admin、YOOGLE 共用同一渲染契约。
- YOOGLE 小搜索与标准窗口搜索；支持球员名、俱乐部、国家队和位置搜索，结果优先有卡画、再按能力排序。
- 三套 UI 窗口标准：标准窗口、加宽窗口、小型窗口。
- 动态天气基础：每地块按真实整点刷新，具有地域倾向和天气连续性；当前只影响比赛模拟。地图天气层默认关闭，开启后使用静态地块颜色、雪花、雨线和雷暴纹理覆盖。
- 远征队视觉素材：1 个默认战棋 + 9 个国家款，已放入素材库，但尚未接入移动系统。
- 设施建造和地图展示骨架已经存在，七类设施的完整玩法效果尚未全部接入。

## M1：远征队与战略移动闭环（下一主线）

目标：让“球队必须从总部或休整设施出发，花真实时间到达目标后才能挑战”成为游戏的核心规则。

1. 建立 Expedition 领域模型与持久化迁移。
   - 状态：驻扎、准备、行军、抵达、挑战中、返程、休整。
   - 记录出发地、目标地、路线、出发/到达时间、阵容快照和战棋样式。
2. 建立移动规则。
   - 陆路仅允许相邻地块推进。
   - 跨海必须从允许出海的地块或港口出发。
   - 路程按真实时间推进，服务器重启后可确定性恢复。
3. 接入地图战棋。
   - 使用 assets/expedition-tokens/manifest.json。
   - 地图显示当前位置、行军路线、剩余时间和选中状态。
4. 接入挑战门槛。
   - 只有抵达目标的远征队可以发起挑战。
   - 同一阵容、球员和目标建立并发锁，避免重复挑战。
5. 接入休整与返回。
   - 总部及指定设施可补给；失败、撤退和挑战结束都有明确去向。
6. 补齐 Admin 观测能力。
   - 查看、筛选、取消异常远征；所有操作写入审计。

完成标准：从总部出发、地图移动、抵达、挑战、结算、返回/休整可以完整跑通，重启不丢状态。

## M2：征服核心规则完善

- 三套独立阵容：联赛阵容、远征进攻阵容、领地防守阵容。
- 球员体力、伤病、停赛跨玩法共享，不复制球员状态。
- 每日挑战次数、失败冷却、撤退成本和连续远征惩罚。
- 防守阵容快照与离线结算。
- PvP 金币托管、幂等结算、目标锁和挑战历史。
- 主客场、跨海体力成本、港口与主场优势参数化。

完成标准：资源、阵容、挑战和领地变化形成可审计、不可重复结算的闭环。

## M3：设施从展示层进入玩法

按依赖顺序接入：

1. 港口：出海资格、海路耗时和补给。
2. 恢复中心：远征休整、体力恢复。
3. 医疗中心：伤病恢复和风险控制。
4. 球探中心：情报、球员和事件线索。
5. 训练中心：受控成长与战术准备。
6. 商店：消耗品和补给。
7. 体育场：主场收益、防守和赛事容量。

设施效果必须由服务端统一结算，前端只展示可解释的结果。

## M4：球员卡、库存与经济

- 球员卡实例、库存、获取来源和唯一 ID。
- 批量制卡与 Admin 发布批次直接进入内容目录。
- 工资、补给、建筑收入、领地收入和完整资源流水。
- 球探、商店、奖励和活动统一通过库存/经济服务发放。
- 所有批量操作支持预览、确认、幂等和回滚记录。

## M5：世界事件与天气扩展

- 建立数据驱动的事件模板、触发器、条件、权重、选项和结果。
- 事件按地区、天气、设施、球队状态和远征阶段分类，不在页面里硬编码。
- 先接入远征遭遇、设施事件、地区事件和赛前事件。
- 天气当前只影响比赛；待远征系统稳定后，再评估行军耗时、补给消耗和事故风险。
- Admin 提供事件开关、权重、预览、灰度和审计。

## M6：玩家领土战争

- 玩家领地挑战、宣战窗口、防守快照和保护期。
- 托管资源、并发锁、断线恢复和争议审计。
- 联盟、协防或赛季领土规则在基础 PvP 稳定后再加入。

## M7：领袖与长期构筑

- 将 S4 教练工作室改造为领袖/指挥官系统。
- 领袖技能影响远征、设施、球探和比赛准备，不直接破坏 26 项球员数值基线。
- 构筑、重置和升级全部配置化。

## M8：赛季、活动与生产化

- 赛季重置策略、荣誉记录、动态目标和大型世界事件。
- PostgreSQL、事务、分布式锁、任务队列、备份恢复和运行指标。
- Admin 完成角色分权、危险操作二次确认、配置版本、回滚和公告能力。

## 持续的 Admin 横向工作

- 保留并扩展 S4 的玩家/球队查询、球员数值、批量制卡、卡画、Excel、比赛审计和内容运营能力。
- 逐步形成八个入口：运营总览、玩家/球队、世界地图、挑战中心、设施/任务、经济、内容工作室、系统/审计。
- 默认账号仅用于本地开发。部署时必须通过 ADMIN_BOOTSTRAP_PASSWORD 设置强密码，并限制 Admin 暴露范围。

## 当前优先级

P0：远征队领域模型、路线与真实时间移动。

P1：远征挑战门槛、休整、阵容/球员锁、地图战棋。

P2：征服闭环规则与港口/恢复/医疗设施效果。

P3：库存经济、随机事件、PvP、领袖、赛季。
