# 连续迷雾、海域走廊与延迟创建（2026-09-05）

本轮在 `codex/rougelite` 上处理用户截图中的八项迷雾问题。取代 fog v1 的整省开雾和永久海上测绘记录；保留建立主场前全图预览、25× 最大倍率、玩家领地配色、既有设施图标及 fog-load v2 城市初始化修复。没有进行此前讨论的 UI 风格统一。

## 已实现行为

1. 以己方实际地理轮廓为源向外扩展连续视野，使用圆角缓冲与柔和渐变。邻省仅露出落入范围的局部，省界不再是迷雾边界。地块仍是归属与征服单位；一部分进入视野后，该地块可以被发现，但被遮住的位置不能通过鼠标点击、城市或设施图标打开。
2. 同一展示区域中，己方岛屿和领地分布围合的海面保持可见；同一 MultiPolygon 地块的离散岛屿也有水上通道。围合范围内的未知陆地仍被遮住，不据此发现其他玩家。
3. 未探索区域的 Atlas 地形网格、树木/灌木实例、湖泊和河口网格延迟创建。视野扩展后小批生成；临时视野消失时释放对应网格，恢复为待创建描述。建立主场后也能回收此前全图预览所创建的无关网格。
4. 迷雾画布固定于视口，拖动时同步重画缓存贴图，不跟随 Leaflet 的可拖动 pane。先填满视口，另补不透明贴图边框，避免快速拖动露底及小数缩放形成细缝。
5. 主地图与小地图共用连续空间模型和遮罩算法；小地图按主地图的探索范围取景，取景框独立绘制在迷雾上方。主地图的最小倍率随探索范围变化，最大仍为 25×。
6. 出海预览只显示合法登陆点周围的小片区域及水上航线。取消立即从本地快照剔除临时目标、天气、攻击目标等；服务端使用预览 ID 关闭，旧关闭请求不能误删新预览。尚未返回的测绘请求在取消后返回，也会关闭其预览。
7. 活跃预览每 30 秒续期，90 秒无人续期自动失效。离开出发地、出发地失守、开始移动、赛季改变或发起征服后也结束预览。预览不存入账号探索历史，重启不恢复。曾实际持有的领地仍保留历史探索灰雾；已经相遇的玩家关系仍保留。

## 实现入口

- `shared/map/fog-spatial.mjs`：服务端/前端共用投影空间索引、几何缓冲、海域围合、可见地块判定、加载范围判定。
- `shared/config/fog.mjs`：schemaVersion 2；普通视野半径 4.5 世界单位，羽化宽度 1.2，登陆预览半径 2.8，存续时间 90 秒；`withoutNavalPreview` 处理本地即时收回。
- `server/application/fog-service.mjs`：探索源、相遇记录、内存预览及失效条件。`server.mjs` / `CampaignService` 已传入真实 GeoJSON。仅无几何的旧测试夹具仍走邻接兼容逻辑。
- `client/map/fog-raster.js`：缓存掩码、海面扣除未知陆地、渐变；显式计算最终 alpha，避免不同 Canvas 合成实现造成差异。单张不超过约 150 万像素/1536 边长。
- `client/map/campaign-fog-controller.js`：视口画布、点可见性、动态镜头边界。
- `client/map/campaign-minimap-controller.js`：同一视野范围与独立取景框。
- `client/maritime/maritime-controller.js`：预览 ID、即时取消、迟到响应清理、续期。
- `POST /api/campaign/maritime/preview`：认证接口，`{previewId, action: "close" | "keepalive"}`。
- `client/map-three/atlas-terrain.js`、`atlas-nature.js`、`campaign-layer.js`：按视野延迟分配及释放；`atlas-environment.js` 按视野限制河流绘制。

## 加载优化的实际边界

这轮实现的是网格/实例延迟分配与回收，并非全部数据的网络分块。GeoJSON、索引、三块区域高程二进制、自然地貌 JSON、基础岸线及雪/自然地表贴图仍预载；基础高程整理和自然地表权重仍有全区域计算。兼容的旧贴图/relief 模式保留原资源加载路径。

`scripts/diagnose-fog-loading.mjs` 在没有浏览器、WebGL 上下文及服务的情况下，用真实资源比较了同一代码的全图和冰岛南部区视野：

| 初始创建项 | 全图 | 冰岛有限视野 |
|---|---:|---:|
| 地形块 | 620 | 12 |
| 地形三角形 | 56,390 | 906 |
| 树木实例 | 18,992 | 128 |
| 灌木实例 | 2,590 | 58 |
| 湖泊 / 河口 | 212 / 18 | 0 / 0 |
| CPU 构建时间（一次本机观测） | 2,163 ms | 1,356 ms |

这些数字不是浏览器首屏时间或 GPU 帧率承诺。详见 `outputs/fog-review/loading-report.json`。后续若要进一步降低网络及基础 CPU 成本，可按地图区域拆分高程/自然数据与地表预处理。
