# Windows 客户端 0.1.2

## 运行与更新

安装 outputs/windows-client-0.1.2/YellowDogs-Setup-0.1.2-x64.exe。仅 Windows x64；安装器尚未代码签名，发布者显示未知。游戏需要联网，不提供离线结算。

客户端复用 https://yellowdogsleague.online/versus/ 的前端与在线 API，不运行本地游戏服务器。地图与图片是公开静态资源；认证、交易、账号状态不会进入自定义资源缓存。

- 安装包自带约 28.8 MiB 核心地图，地图 URL 的内容哈希匹配时可直接使用；无需先下载全部图片。
- 其他图片按需下载，SHA-256 和大小校验通过后落盘。同一资源的并发下载合并，失败重试一次。
- 启动检查线上 /assets/data/desktop-resources.json。核心资源全部就绪后切换清单，失败保留原清单和已验证文件。
- 清单使用 gzip + ETag，后续启动会验证版本，未变化时不重复传输全文。
- 跨次启动保留缓存；历史资源在同步结束时按 1 GiB 预算清理。此预算针对下载缓存，不含随包地图和 Chromium 自身缓存。
- 资源管理提供更新、校验与修复、清理缓存。清理保留随包地图与登录数据；需要先关闭游戏窗口。
- 客户端程序目前通过新版安装包覆盖更新，保留用户数据；尚未接入签名自动升级源。游戏网页和资源可以独立更新，不需要每次重装客户端。

当前服务器 R13 没有桌面清单时，显示在线备用模式：匹配的随包地图仍可用，其余资源按网页方式加载。部署 R15 累计更新包后启用完整资源清单同步（不需要先安装 R14）。不要把桌面运行时上传到游戏服务器。

## 构建

在 windows-client 目录使用 PowerShell 7：

```powershell
npm ci
npm test
npm run build
```

build-resources.mjs 生成随包核心资源和服务器公开清单。增量热更新构建脚本也会调用 --manifest-only 重新生成清单，避免线上素材与清单脱节。Electron 依赖与服务器依赖分离。

本次依赖下载使用 npm 镜像；版本与完整性值记录在 package-lock.json。签名证书尚未配置；发布前可配置 electron-builder 的签名设置，并启用 executable 元数据编辑。本版没有伪造发布者或绕过 Windows 信任检查。

## 边界与验证

- 游戏 renderer 禁用 Node，启用 sandbox/contextIsolation/webSecurity；不注入本地文件或系统命令接口。
- 资源管理 IPC 只接受本地窗口主 frame。游戏窗口限制同源导航，拒绝新窗口和设备权限。
- 静态缓存按固定线上域名及经过验证的清单读取；不拦截 API、跨域地址、带认证请求或 Range 请求。
- Electron 实际启动及打包后启动已验证：Node API 不可见，随包地图读取 4,494,979 字节，下载次数为 0。
- 单元测试覆盖并发去重、跨启动复用、坏文件、失败回退、清理隔离、URL/路径边界及清单 gzip/304。
- 未使用真实玩家账号执行对局或交易；服务器 OOM 和网页运行时解析/重绘成本不会因使用 Electron 自动消失。

故障时保留资源管理提示，先使用“校验与修复”。完整退出客户端后覆盖安装可修复随包文件损坏。

0.1.2 修复首次连接失败后重试无效：失败窗口关闭，重新进入会真正重载；30 秒连接等待上限；防止重复点击同时开窗；短窗口高度优化。10 项单测及实际 Electron 失败重试与本地地图命中验证通过，未证明修复公网 CDN 链路。
